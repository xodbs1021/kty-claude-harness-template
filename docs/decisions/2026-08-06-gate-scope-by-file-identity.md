# ADR-0007: 완료 게이트 검사 범위는 위치가 아니라 파일 정체성으로 정한다

Status: accepted
Date: 2026-08-06
관련: PR #14, ADR-0005(커밋 분할 근거)

## Context

완료 게이트(`.needs-audit`·`.needs-explain`·`.needs-vault`·`.needs-dualreview`)를 세우는
`mark-needs-audit.sh` 는 **"편집한 파일이 `PROJECT_DIR` 안인가"** 로만 판정했다. 밖이면 통째로 스킵했다.

그런데 하네스 자신을 고치는 작업은 **항상 `PROJECT_DIR` 밖 별도 클론**에서 일어난다.
2026-08-04 실사고: 하네스 템플릿을 고치는 턴에 게이트가 하나도 서지 않아 검증 없이 끝났다.
게이트가 프로젝트는 지키면서 정작 게이트 자신을 만드는 작업만 못 지켰다.

이 부류는 **조용히 틀린다** — 플래그가 안 서도 에러가 없다. 그래서 규칙을 산문으로만 두면
언제 무너졌는지도 알 수 없다.

첫 시도(`38b36f6`, 미머지)는 "밖이라도 git 저장소 안이면 그 저장소 기준으로 검사"를 도입했으나
차단급 결함 4건이 남았다. 그중 하나는 **설계·계획 산출물 판정이 경로 정규화보다 먼저 돌아**
고치려던 그 지점이 그대로 남은 것이었다.

## Decision

**판정 기준을 "어디 있나"에서 "무슨 파일인가"로 옮긴다.**

| 입력 | 판정 |
|---|---|
| `PROJECT_DIR` 안 | 기존대로. 최상위 `_workspace/`·`.claude/` 와 순수 문서 제외 |
| 밖 + **하네스 정본 저장소**(루트에 `template/.claude/`) | 저장소 전체를 **프로젝트와 같은 규칙으로** 검사 |
| 밖 + 그 외 | `.claude/` 에 앵커된 하네스 경로만. **git 저장소가 아니어도 발화** |
| `_workspace/00_design*.md`·`01_plan*.md` | 위치·git 여부 무관하게 듀얼리뷰 플래그만 |

부수 결정 셋:

1. **판정 순서가 곧 계약이다.** 개행 가드 → 물리 경로 정규화 → 듀얼리뷰 판정 → 범위 판정 → 분류 → 기록.
   순서를 뒤집으면 조용히 판정이 바뀌므로, 각 순서를 지키는 테스트 행을 따로 둔다.
2. **밖 편집은 절대경로로 기록한다.** 상대경로면 프로젝트와 외부 저장소가 `README.md` 같은 흔한 경로를
   공유할 때 감사자가 프로젝트 쪽 동명 파일을 보고 통과시킨다.
3. **조용한 실패를 없앤다.** 정규화 실패는 스킵하지 않고 원본 경로로 판정을 잇는다(fail-loud).
   플래그 쓰기 실패·경로 개행·git 거부는 **차단하지 않고**(PostToolUse 계약) `systemMessage` 로 알린다.

**계약의 정본은 산문이 아니라 `tests/mark-needs-audit.cases.sh` 의 판정 표**다. 케이스 수는 같은 파일의
`EXPECTED_CASES` 가 강제하고 CI 가 PR 마다 돌린다. 문서에는 개수를 적지 않는다.

## Alternatives Considered

**A. `$HOME` 접두사 예외 유지 (첫 시도의 방식)**
- Pros: 명세 문구에 가장 가까움. 변경 폭 작음
- Cons: 양방향으로 틀린다. `~/dotfiles` 는 안 걸러지고, `~/.claude` 가 git 저장소인 셋업에서는
  그 아래 하네스 클론이 조용히 스킵된다. **위치 기준 자체가 원인**이라 예외를 더해도 새 예외가 필요해진다
- Why not: 채택안은 예외 규칙 없이 같은 결과를 낸다

**B. 밖에서도 제외 목록 방식으로 코드 전반 게이트**
- Pros: 하네스 파일을 놓칠 일이 없다
- Cons: 남의 저장소를 잠깐 고쳐도 게이트 4종이 선다. 오탐이 많아 탈출구를 상시로 쓰게 되고,
  그러면 게이트 자체가 무력화된다
- Why not: 오탐 비용이 위음성 방지 이득을 넘는다

**C. 정본 마커에 `template/.claude/hooks/_common.sh` 존재까지 AND 조건**
- Pros: 오탐 표면이 준다
- Cons: **위음성을 넓힌다.** 그 파일이 없는 하네스 포크에서 이전 판에는 서던 게이트가 사라진다.
  "비용 0"이라 판단했으나 codex 검수가 반증했다
- Why not: 오탐(과하게 섬)보다 위음성(조용히 안 섬)이 나쁘다는 이 게이트의 기본 방향과 충돌

**D. 설계·계획 문서 판정을 git 저장소 안일 때만**
- Pros: 명세 문구 그대로
- Cons: **실측으로 반증됨** — 이 작업의 `_workspace/` 자체가 어느 git 저장소에도 속하지 않는다(rc=128).
  그대로 두면 "설계만 한 턴은 게이트 0개"인 원 실사고가 그대로 남는다
- Why not: 고치려던 사고를 못 고친다

## Consequences

**Positive**
- 하네스 저장소·홈 설치본을 고치는 작업이 프로젝트 작업과 같은 무게를 갖는다.
  "하네스는 툴이니까 가볍게"가 기계적으로 불가능해졌다
- 판정 규칙이 표로 고정돼 CI 가 강제한다. 되돌림 실측과 변이 주입으로 테스트가 실제로 결함을 잡는 것을 확인했다
- 예외 규칙(`$HOME`)이 사라져 규칙이 한 층 얕아졌다

**Negative**
- **정본 마커 오탐** — 루트에 `template/.claude/` 를 둔 제3 저장소를 하네스로 오인할 수 있다.
  피해 방향이 "과하게 섬"이고 탈출구(`ECC_DISABLED_HOOKS=post:edit:needs-audit`)가 있어 감수한다
- **반대 방향 위음성** — `template/.claude/` 를 두지 않는 재배치 포크는 정본으로 인식되지 않는다.
  그런 포크는 현재 없고, 마커를 단순하게 유지해 예측 가능성을 택했다
- **하네스 작업 턴이 길어진다.** 게이트 4개를 다 밟아야 끝난다. 버그가 아니라 의도다
- 모노레포 하위 패키지가 자기 `.claude/` 를 가지면 게이트가 선다. **이번 변경이 만든 게 아니라
  구판에도 있던 동작**이며, 고치는 것은 범위 밖이라 케이스로 기록만 했다

**과정에서 배운 것 (다음 사람용)**
- **"겹치는 파일 0개"는 리베이스 생략의 근거가 못 된다.** 이 PR 도중 `main` 이 앞서 갔는데(#13)
  파일이 안 겹친다는 이유로 리베이스를 생략했다. 그 결과 **#13 이 형제 함수에서 방금 고친 버그**
  (논리 `cd` 가 `심링크/..` 를 오판)를 새 함수가 그대로 들고 들어왔다. 텍스트 충돌이 아니라 의미 충돌이었다.
  → 직전 커밋들이 **무엇을 고쳤는지**를 파일 목록이 아니라 내용으로 확인해야 한다
- **검증 절차 자체가 작업물을 지울 수 있다.** 되돌림 실측에 `git checkout -- <파일>` 을 쓰면
  인덱스의 구판이 복원돼 새 구현이 사라진다. `cp` 백업/복원만 쓴다
- **`2>/dev/null` 은 리다이렉트 *열기* 실패를 못 막는다.** 셸이 그 전에 보고한다. 복합명령으로 감싸야 한다
- **명령 치환은 후행 개행을 먹는다.** 그래서 경로 끝 개행은 가드가 보기도 전에 사라진다. 센티널 캡처가 필요하다
