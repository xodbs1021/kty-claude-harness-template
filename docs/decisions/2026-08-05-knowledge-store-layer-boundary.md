# ADR-0006: 지식 저장소는 상위 층이다 — 하네스는 계약만 알고 구현을 모른다

**Date**: 2026-08-05
**Status**: accepted (이행 완료 2026-08-10 — 아래 "이행 결과")
**Deciders**: 김태윤(계층 정의·요구 확정), Claude(위반 실측·설계)

---

## Context

kty의 시스템은 두 덩어리다.

| | 무엇 | 성격 |
|---|---|---|
| **second brain / llm wiki** (볼트) | kty의 **모든** 지식을 담는 곳 | **상위.** 하네스가 없어도 존재한다 |
| **harness** (이 저장소) | 프로젝트를 잘 수행하려고 만든 도구 | **하위.** 상위를 참조할 수 있다 |

kty가 못박은 요구: **각자 따로 설치돼도 문제없이 돌아가야 한다.**

### 지금은 그 요구가 깨져 있다

2026-08-02 "볼트 반영 산문 규칙이 세션 내내 0회 이행" 실사고 뒤, 이 저장소의 교훈("산문으로만 존재하는 절차는 훅·게이트로 승격하라")에 따라 볼트 반영을 완료 게이트로 올렸다. 그런데 **완료를 강제하는 기계가 하네스뿐**이라, 갈 곳이 없어 볼트 지식이 글루 층으로 들어갔다.

실측 — `template/` 아래 볼트 고유 표현 **10건 / 4파일**:

| 파일 | 무엇이 새어 있나 |
|---|---|
| `template/.claude/skills/harness-orchestrator/SKILL.md` | `Projects/<name>/` 4종 세트, `_CLAUDE.md`, `specs/`, `second brain` |
| `template/.claude/hooks/mark-needs-audit.sh` | `.needs-vault` |
| `template/.claude/hooks/verify-before-stop.sh` | `.needs-vault` |
| `template/.claude/hooks/_common.sh` | `.needs-vault` |

`README.md`가 이 저장소를 *"제네릭 에이전트 8 (**도메인 누출 0**)"* 이라 설명하고, 탄생 이유를 *"도메인 지식이 에이전트 5+곳에 산재 → 단일 프로필 슬롯"* 이라 적었다. **자기 원칙 위반이다.** 그리고 제0원칙 4번(**구체가 아닌 계약에 의존** — DIP)에도 걸린다.

**의존은 한 방향뿐이다.** 볼트 코드가 하네스를 읽거나 존재를 전제하는 곳은 0건이다(`_CLAUDE.md`·`sync_adr.py`의 "하네스 운영 등" 3건은 결정 분류 **예시**). 하네스를 지워도 볼트는 정상 작동한다. 반대는 지금 깨진다 — 볼트 없이 설치하면 게이트가 존재하지 않는 구조를 요구한다.

## Decision

**계약은 하네스가 소유하고, 볼트는 그 계약의 구현체 중 하나이며, 둘을 잇는 설정은 사용자 층에 둔다.**

```
① 계약 (하네스 소유)
   "지식 저장소가 설정돼 있으면, 결정·설계가 나온 턴은 반영 없이 끝낼 수 없다"
   볼트를 언급하지 않는다. 경로도 구조도 모른다.

② 구현체 (볼트 소유)
   Projects/<name>/ 4종 세트 · _CLAUDE.md · specs/ · 인덱스 등재
   하네스를 모른다.

③ 접착 (사용자 층 — 전역 CLAUDE.md)
   "이 머신의 지식 저장소는 볼트다" + 그 형식 안내
```

**슬롯은 이미 있는 관용구를 쓴다.** `harness.env`의 `HARNESS_TYPECHECK_CMD=""`가 *"비우면 Stop 훅이 타입체크를 생략한다"* 인 것과 같은 모양으로:

```bash
# 지식 반영 게이트. 비우면 생략한다(지식 저장소를 안 쓰는 환경).
# 어디에·어떤 구조로 반영하는지는 이 파일이 모른다 — 사용자 전역 설정이 답한다.
HARNESS_KNOWLEDGE_GATE=""
```

**훅은 경로를 알 필요조차 없다.** 하는 일이 "플래그가 섰는데 안 지워졌으면 종료 차단"이라 켜짐/꺼짐 하나면 된다. *어디에 어떻게 저장했는지의 검증은 볼트 자기 훅(4종 세트 pre-commit)이 이미 한다.*

플래그 이름도 계약 수준으로 올린다: `.needs-vault` → `.needs-knowledge`.

## Alternatives Considered

### A. 볼트가 인터페이스를 소유하고 하네스가 구현체
- **Pros**: 상위 층이 규격을 정한다는 직관에 맞음
- **Cons**: 인터페이스를 알려면 볼트가 있어야 한다 → **볼트를 지우면 하네스가 자기가 뭘 호출할지 모른다.** kty의 "각자 단독 작동" 요구와 정면 충돌. 지금 상태가 정확히 이것
- **Why not**: 요구를 못 지킨다

### B. `install.sh` 가 볼트 설치 여부를 **탐지**
- **Pros**: 사용자가 설정을 안 해도 됨
- **Cons**: 탐지하려면 경로·구조를 알아야 한다 → **걷어내려는 결합을 다시 도입한다.** 볼트를 다른 경로에 뒀거나 나중에 설치하면 틀린다
- **Why not**: 확인(detect)이 아니라 설정(configure)이어야 층이 유지된다. 대화형으로 **묻는** 것은 허용(사용자에게 위임이라 하네스가 볼트를 알게 되지 않음), 단 비대화형 설치를 깨뜨리므로 선택지일 뿐

### C. `project-profile.md` 에 §10 "지식 저장소" 슬롯 신설
- **Cons**: 프로필은 **프로젝트별**인데 지식 저장소는 **사용자별**이다. 프로젝트마다 같은 값을 적으면 언젠가 어긋난다
- **Why not**: 중복이 드리프트를 만든다. 실제로 이 저장소는 문서 숫자 하나가 일곱 번 낡는 걸 겪었다(PR #10)

### D. 아무것도 안 하고 산문으로 둔다
- **Why not**: 2026-08-02 실사고가 정확히 그래서 났다

## Consequences

### Positive
- **도메인 누출 0 회복** — 하네스가 다시 도메인-무관 글루가 된다
- **교체 가능** — 볼트를 Notion 등으로 바꿔도 하네스는 안 고친다(제0원칙 3)
- **양쪽 단독 설치 정상** — 볼트 없으면 게이트 no-op, 하네스 없어도 볼트 그대로
- 새 메커니즘 0개 — 기존 슬롯 관용구 재사용

### Negative
- 사용자가 한 줄을 켜야 게이트가 산다. 안 켜면 조용히 안 돈다 — `install.sh` 안내 문구로 완화
- 기존 설치본은 `sync.sh` 후 슬롯을 채워야 한다(슬롯은 보존되므로 자동으로 안 켜짐)

## 기계적 장치 — 산문으로 두지 않는다

이 경계는 **grep으로 판정 가능하다.** 조회 라우팅 같은 "행동"과 달리 "글루에 상위 층 구현이 있나"는 기계가 100% 답한다.

`scripts/check-layer-boundary.sh` (신설 예정):
- `template/` 아래에서 상위 층 고유 표현을 찾으면 `exit 1`
- 금지 목록: 볼트 경로 · `second brain` · `_CLAUDE.md` · `4종 세트` · `Projects/<name>/` · `needs-vault`
- CI(`check-rules.yml`)에 스텝 추가
- 메시지: "하네스 글루에 상위 층 구현이 샜다 — 계약만 남기고 구현은 사용자 층으로"

이 검사는 볼트에 한정되지 않는다. **`README.md`가 선언한 "도메인 누출 0"을 처음으로 기계가 지키게 된다.**

## 이행 결과 (2026-08-10)

`refactor/knowledge-store-layer` 에서 이행했다.

- **누출 정리**: `template/` 아래 상위 층 표현 **13건/4파일 → 0건**. 훅 3개(`_common.sh`·`mark-needs-audit.sh`·`verify-before-stop.sh`)와 오케스트레이터 스킬에서 구현을 걷어내고 계약 문장만 남겼다
- **플래그 개명**: `.needs-vault` → `.needs-knowledge`
- **슬롯 신설**: `harness.env` 의 `HARNESS_KNOWLEDGE_GATE`. 판독 규칙과 기본값은 [ADR-0008](2026-08-06-knowledge-gate-default-on.md) 로 갈라졌다 — 이 ADR의 *"슬롯을 비우면 생략"* 관용구를 **일부 supersede** 한다. 기존 설치본에 키가 없으므로 "없음 = 꺼짐"이면 업그레이드가 게이트를 조용히 끈다. 그래서 **없으면 켜짐**이다
- **접착 층 안내**: `CLAUDE.md.snippet` 에 "지식 저장소 연결은 전역 `CLAUDE.md` 가 답한다"를 명시
- **기계 강제**: `scripts/check-layer-boundary.sh` + CI 스텝. 회귀 테스트 14건이 그 검사기를 지킨다
- **조회 방향**: 이행 중에 프로필 정본 위치 문제가 갈라져 나와 [ADR-0009](2026-08-06-profile-canon-upstream.md) 가 됐고, 회수 **정책**은 미설계로 [ADR-0010](2026-08-06-knowledge-retrieval-policy.md) 에 못박았다

**"금지 목록"의 실제 구현은 설계와 조금 다르다.** 여기서는 목록만 적었는데, 구현은 각 패턴에 **왜 상위 층인가**를 붙였다 — "금지됐다"만 알려주는 검사는 걸린 사람이 무엇을 계약 수준으로 다시 써야 하는지 몰라 우회당한다.

**설계 당시의 우려 하나는 빗나갔다.** *"정리 완료 후에 검사기를 켜라(지금 켜면 즉시 빨간불)"* 이라고 적었는데, 실제로는 검사기를 먼저 만들고 그것으로 누출을 **찾아가며** 정리하는 편이 빨랐다. 13건은 손으로 세었을 때보다 3건 많았다.
