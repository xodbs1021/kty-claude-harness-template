# ADR-0005: 커밋 분할의 근거는 롤백 독립성이 아니라 리뷰 가독성이다

**Date**: 2026-08-05
**Status**: accepted
**Deciders**: 김태윤(규칙 소유), Claude(분할 시도·실측), codex(근거 반증)

---

## Context

이 저장소의 규칙은 **"롤백 단위가 다른 변경을 커밋에 섞지 말 것"**이다. PR #9이 이 규칙을 어겨(규칙 동기화 + 게이트 범위 변경 혼재) 닫혔다.

PR #10에서 그 규칙을 적용해 커밋을 A(워크플로 `permissions`)와 B(위음성 수정 본체)로 나눴다. 근거는 *"A는 되돌려도 아무 테스트가 깨지지 않는 **독립 롤백이 성립하는 유일한 축**"*이었다.

여기에 보안 검수가 `persist-credentials: false` 한 줄을 요구했고, **그 4줄을 어디 둘지가 세 번 바뀌었다.**

| 시도 | 배치 | 결과 |
|---|---|---|
| 1차 | A에 포함 (`permissions`와 같은 CI 하드닝 축) | **`git revert A` 충돌.** A의 `with:` 블록이 B가 추가한 테스트 스텝과 인접해 컨텍스트가 어긋남 |
| 2차 | B로 이동 ("B가 PR 작성 셸을 CI에서 한 번 더 실행하게 만드니 같은 서사") | codex가 `git show 357e24f:.github/workflows/check-rules.yml`로 **그 시점에도 이미 PR 작성 스크립트를 실행 중**이었음을 실측 → 위험은 B가 만든 게 아니라 원래 있던 것 → 근거 붕괴 |
| 3차 | **C로 분리, 맨 뒤 배치** | `git revert C`·`git revert A` 둘 다 무충돌. 되돌린 상태에서 회귀 테스트 전건 통과 |

## Decision

**A·B·C 3분할을 유지하되, 근거를 "리뷰 가독성"으로 재서술한다.**

squash 머지 전제이므로 머지 시점에 A·B·C 구분은 사라진다. **롤백 단위 논리는 머지 전에만 유효**하고, 분할의 실제 이득은 리뷰어가 축을 나눠 볼 수 있다는 것이다.

C를 맨 뒤에 둔 이유: 뒤따르는 커밋이 없어야 revert가 깨끗하다. 1차가 충돌한 원인이 정확히 "뒤 커밋이 인접 영역을 건드림"이었다.

**완전하지는 않다.** 이 배치에서 **커밋 B 단독 revert는 충돌한다** — C의 4줄이 checkout 스텝 바로 뒤에 붙고 B가 추가한 스텝이 그 다음 줄이라서다. 순서를 뒤집으면 반대쪽이 충돌한다. **셋 다 깨끗한 배치는 없다.** PR 본문에 공시했다.

## Alternatives Considered

### A. 2분할 유지하고 `persist-credentials`를 B에 둔다
- **Cons**: 저장소 규칙 위반. codex가 독립 축임을 실측으로 보였다
- **Why not**: 이 규칙을 어겨서 PR #9이 닫혔다. 규칙을 세운 당사자가 반복하면 안 된다

### B. 별도 PR로 뺀다
- **Pros**: 완전히 독립
- **Cons**: 4줄짜리 PR. 검사기가 아직 머지되지 않아 독립적으로 존재할 대상이 없다
- **Why not**: 과분할(제0원칙 5)

### C. 3분할 + 근거 재서술 — **채택**

## Consequences

### Positive
- A·C 각각 **실제 `git revert`**로 무충돌 실증(`git apply --check`가 아니라)
- PR 본문의 근거가 실물과 일치한다

### Negative
- B 단독 revert는 여전히 충돌 — 공시로 처리
- 커밋이 늘어 리뷰 대조가 조금 번거롭다

## 이 저장소가 가져갈 교훈

1. **`git apply --check`와 실제 `git revert`는 결과가 갈린다.** 롤백 검증은 실제 revert로 해야 한다 — PR #10에서 실제로 갈렸다
2. **"롤백 단위" 주장은 squash 전제에서 검증 불가능한 서술이 되기 쉽다.** 머지 후엔 구분이 사라지므로 분할의 진짜 이득은 리뷰 가독성이다. 그렇게 쓰는 편이 정직하다
3. **커밋 배치는 hunk 인접성이 지배한다.** 논리적 축보다 물리적 위치가 revert 성공 여부를 정한다
