# 설계서 — 레퍼런스 조사 게이트 (ADR-0015 대상)

작성: 2026-08-11 · 브랜치 `feat/reference-research-gate` (main = `c25a0c7`)

## 0. 요구 원문과 확정 요지

**kty 요구 원문 요지:** *"계획 세울 때 레퍼런스 조사를 강제했으면 한다. 내가 그냥 조사해오라고
했으면 너는 절대 Netflix 조사 안 했을 거다 — 라이브 스트리밍 서비스가 아니니까. 조사가
필요하다고 판단되는 지시사항에 대해서만, 기계적 게이트로 무조건 실시하게 할 수 있나?"*

**확정 설계 요지 (kty, 2026-08-10):** "조사가 필요한 지시인가"의 **판정은 기계 불가**(임의
목록 부류). 대신 판정의 **무표명 통과**를 기계로 막는다 — ADR-0013 과 같은 구조:

- 계획·설계 산출물에 `레퍼런스 조사: 조사함(<대상·출처>)` 또는 `불요(<사유>)` 표명 의무.
  **불요에도 사유 강제**가 핵심(조용한 스킵 불가화)
- Stop 게이트가 **형식만** 검사 (회수 게이트 3.4 와 같은 기계)
- 조사 계약에 **인접 도메인 포함** 명시 — "우리가 라이브면 VOD·저장·CDN 도 본다".
  실증: pokeclip 사이드카의 답이 "라이브 아닌 Netflix"가 아니라 **Netflix Live Origin**
  (2025-12 TechBlog — S3→KV 전환, payload chunking, segment-template manifest)에 있었다
- 조사 실행은 전역 에이전트 `research-collector`(수집) → `research-evaluator`(독립 검증)
- 검수(plan-reviewer·codex)가 **불요 사유의 타당성과 조사 품질**을 심사 (산문 계약 공시)

**판정 프레임 정합(ADR-0013 의 구분):** 이 표명은 **새 의무의 신설**이다 — 관측 우선 규칙의
적용 대상. 그 관측은 이미 있다: pokeclip 미디어 사이드카(DVR·S3) 설계에서 선행 기술 조사가
실제로 0회였고 kty 가 그 누락을 실물로 짚었다(위 계기 사례). "실제로 새는 것을 본 뒤"라는
전제가 충족됐으므로 의무 신설이 정당하다. 신설된 의무의 **형식 검증**은 그 순간부터
산문 승격 부류가 된다 — 산문 절차 불이행은 이 저장소가 반복 실측한 부류다(2026-08-02
볼트 반영 0회 · 2026-08-03 듀얼리뷰 생략 — ADR-0013 Alt E 와 같은 논거).

## 2. 용어 (ADR-0013 의 3분법을 이어받아 하나 보탠다)

- **판정**(조사가 필요한 지시인가) — 기계 불가. 산출물 작성자(architect·planner)와
  오케스트레이터의 판단, 검수(LLM)의 심사 대상
- **실행**(조사를 실제로 하는 것) — research-collector → research-evaluator (산문 계약)
- **표명**(판정·실행의 결과를 적는 것) — 산출물 둘째 줄. **여기만 기계**
- **심사**(불요 사유·조사 품질) — plan-reviewer·codex 검수 (산문 계약)

## 3. 결정 ① — 게이트 형태: 3.4 를 "산출물 머리 표명 게이트"로 일반화한다

3.4 게이트가 파일마다 검사하는 항목을 하나에서 둘로 늘린다: 첫 줄(회수 표명 — 현행 그대로)
+ **둘째 줄(레퍼런스 표명 — 신설)**. 신설 부품은 검사 항목 하나뿐이고, 상태기계는 전부
기존 것을 재사용한다:

| 상태기계 부품 | 재사용 방식 |
|---|---|
| 플래그 | `.needs-retrieval` 그대로 — 같은 파일 집합(`00_design*`·`01_plan*`), 같은 트리거, 같은 생명주기 |
| `work_pending`·조기 종료 | `retrieval_pending()` 그대로 — 신규 항 없음 |
| 공유 지문(`flags_fp`) | `r` 존재 비트 그대로 — 신규 비트 없음 |
| 예산 키 | `retrieval:<정렬된 불량 경로 목록>` 그대로 — 불량 사유는 키에 넣지 않는다(아래 ③-2) |
| 자동 해제 + 재평가 + 지문 재계산 | 그대로 — "두 검사 모두 형식 준수(또는 소실뿐)"일 때만 해제 |
| `decision_armed` 비편입 | 그대로 (r17 계약 유지) |
| 개행 없는 마지막 줄(`\|\| [ -n ]`) | 그대로 (r26 계약 유지) |
| mark-needs-audit | **변경 없음** — 플래그 5종·기록 로직·cases.sh 동일. FLAG_NAMES 불변 |

**근거:**
- ADR-0012 ⑥ "범위→단순": 두 표명은 대상 파일·트리거·형태(머리 줄 접두어+내용)·해제
  의미(형식을 지키면 스스로 풀림)가 전부 동일하다. 다른 것은 검사하는 줄과 문법뿐이다 —
  이것은 게이트의 **범위**(무엇을 검사하나)이지 새 판정이 아니다.
- 신설안(`stop:reference` + `.needs-reference`)은 직전 세션 검수가 잡은 상태기계 결합
  전부를 다시 지나야 한다: work_pending 편입 · flags_fp 존재 비트 · 게이트별 예산 키 ·
  예산 소진 rm/changed 목록 · 자동 해제 후 재평가 · compute_flags_fp 재계산 ·
  decision_armed 비편입 · 플래그 마지막 줄 개행. 여덟 결합면 각각이 실측 결함이 났던
  자리다(`specs/2026-08-10-회수정책-검수-실측.md`). 같은 지뢰밭을 정보 이득 없이 두 번
  걷는 설계다.
- **대가 (공시):** `ECC_DISABLED_HOOKS=stop:retrieval` 하나로 두 표명 검사가 함께 꺼진다.
  개별 끄기는 불가능하다. 수용 근거: 두 표명은 같은 산출물의 같은 머리 블록이고, 게이트
  끄기는 상시 운영이 아니라 비상 탈출구다. 개별 끄기 수요가 실측되면 그때 분리를 재검토
  (관측 우선). 게이트 ID 는 기존 배포 문서와의 호환을 위해 `stop:retrieval` 을 유지한다 —
  이름이 좁아 보이는 것도 공시 대상이다(usage.md 에 "두 표명을 함께 검사" 명기).

**기존 27케이스·18변이 보존 방식:** 기존 케이스의 **단언은 전부 불변**이다. 다만 "정상
산출물" 픽스처(`GOOD_FIRST` 한 줄)가 새 계약에서는 둘째 줄 불량이 되므로, 픽스처 생성부를
"정상 머리 2줄"로 갱신한다(`mk_doc` 의 GOOD 경로). 불량 픽스처(r03~r06 등)는 그대로 —
첫 줄 불량은 여전히 첫 줄 사유로 차단된다. 변이 18종의 앵커는 첫 줄 검사·상태기계 쪽이라
영향이 없고, 기준선(변이 전 전건 초록)을 실측으로 재확인한다.

### 기각 대안 (①)

- **A. `stop:reference` 신설** — 위 결합 8종 재주행. 개별 끄기 이득은 관측 없음. 기각.
- **B. 표명을 산문으로만 (게이트 없음)** — 산문 절차 불이행 실측 부류(ADR-0013 Alt E 와
  동일 논거) + kty 가 "기계적 게이트"를 명시 요구. 기각.
- **C. "조사 필요" 판정 자체를 기계로 (키워드·카테고리 목록)** — 임의 목록 부류
  (ADR-0012 ⑥). kty 확정 요지가 이미 기각했다. 기각.

## 4. 결정 ② — 표명 자리: 머리 2줄 고정, 회수 블록은 셋째 줄부터

산출물 머리가 다음으로 고정된다:

```
1줄: 사전 결정 회수: <읽은 경로>            또는  사전 결정 회수: 없음(<사유>)
2줄: 레퍼런스 조사: 조사함(<대상·출처>)      또는  레퍼런스 조사: 불요(<사유>)
3줄~: - 걸리는 선행 결정: <제목 — 한 줄>     (0건이면 - 걸리는 선행 결정 없음)
```

**근거:**
- 첫 줄은 `사전 결정 회수:` 가 선점했다(ADR-0009·0013 — 배포된 계약, 옮기지 않는다).
- 회수 블록은 가변 길이(걸리는 결정 수만큼 불릿)라 "블록 다음 줄" 앵커는 기계 판정이
  성립하지 않는다. "N줄 이내" 스캔은 임의 숫자 부류(ADR-0012 ⑥). 파일 전체 스캔은 머리
  표명이라는 형태를 잃고 문서 아래 묻힌 표명을 허용한다. **둘째 줄 고정**만이 임의 숫자
  없는 결정적 앵커다.
- 회수 블록의 위치는 **산문 계약**(ADR-0013 ⑴ "첫 줄 직후")이고 기계는 첫 줄만 봤다 —
  블록을 셋째 줄로 옮기는 것은 산문 계약 텍스트 3곳(SKILL dispatch 계약 2행 · Phase 2
  확인 문단 · 프로필 9절)의 갱신이며 기계 계약 변경이 아니다. ADR-0015 가 ADR-0013 ⑴의
  이 문구를 명시적으로 갱신한다고 적는다(supersede 아님 — 블록 형식·의미는 불변).

**BOM·CR 처리:** BOM 은 파일 첫머리에만 오므로 첫 줄만 스트립(현행). CR 은 두 줄 모두
스트립(r25 의 짝으로 둘째 줄 CR 케이스 신설).

### 기각 대안 (②)

- **D. 파일 내 어디든 허용** — 앵커 상실·머리 형태 상실·검수가 찾아 헤맴. 기각(사용자 확정).
- **E. 회수 블록 뒤(가변 위치)** — 기계 판정 불성립. 기각.

## 5. 결정 ③ — 형식 문법과 검사 알고리즘

### ③-1 문법 (닫힌 문법 — 이 밖은 전부 불량)

```
레퍼런스 조사:<공백*>조사함(<내용>)<공백*>
레퍼런스 조사:<공백*>불요(<내용>)<공백*>
```

- `<내용>` = 공백만이 아닌 문자열(내부 괄호 허용 — 마지막 `)` 가 닫는 괄호)
- 변형 단어와 여는 괄호 사이 공백 허용(`조사함 (…)` — 단어 꼬리 공백 트림)
- 닫는 괄호 뒤에는 공백만 허용 — 꼬리 잡음(`불요(x) 추가설명`)은 불량. 정보는 괄호 안에
  적는 닫힌 문법을 유지해야 "괄호 밖으로 사유를 빼는" 우회가 안 생긴다

**회수 표명(첫 줄)보다 검사가 두꺼운 이유:** 회수 표명의 정상형에는 자유 형식(`<경로>`)이
있어 "접두어+비어있지 않음"이 검사 가능한 최대치다. 레퍼런스 표명은 kty 가 형식을 두
형태로 닫아 줬고, 핵심 요구(**불요에도 사유 강제**)가 정확히 "변형+괄호 내용" 깊이에서만
기계화된다 — 접두어 검사만 하면 `레퍼런스 조사: 불요` 가 통과해 사유 강제가 산문으로
밀린다. 내용의 **진실성**은 여전히 검수 몫이다(형식 검사의 상한 — ADR-0013 ④ 유지).

### ③-2 검사 알고리즘 (3.4 루프 내부 변경)

```
파일마다:
  머리 2줄을 읽는다 (블록 리다이렉트 1회 — 파일을 두 번 열지 않는다)
  1줄 판정: 현행 그대로 (BOM·CR 스트립 → 접두어 → 내용 비어있지 않음)
  2줄 판정: CR 스트립 → 접두어 `레퍼런스 조사:` → 몸체 트림 →
            변형(조사함|불요) → `(` 존재 → 끝이 `)` → 괄호 안 비어있지 않음
  실패한 판정마다 "경로 — 사유" 를 불량 목록에 추가 (한 파일이 두 줄 다 불량이면 두 항목)
```

- 둘째 줄이 아예 없으면(1줄 파일·빈 파일) — 사유 "둘째 줄 없음(레퍼런스 표명 누락)".
  개행 없이 끝나는 둘째 줄은 `read || [ -n ]` 관용구로 읽는다(r26 과 같은 부류)
- 불량 사유 문자열은 게이트 메시지에만 실린다. **예산 키에는 경로만** 들어간다(현행) —
  같은 파일의 사유가 1→2개로 바뀌는 것을 진전으로 세지 않는 대신, 파일 단위 수정(한 번의
  편집으로 두 줄을 고침)이 자연 단위라 키 안정성이 우선이다
- 차단 메시지의 "해야 할 일"에 두 형식 전문과 회수 블록 셋째 줄 이동을 안내한다

### ③-3 기각 대안 (③)

- **F. URL 정규식 의무** — 유효 출처 형태(사내 문서·서적·수집물 경로)를 임의 목록으로
  좁히고 내용 검사에 침범. 출처의 재검증 가능성 심사는 검수 몫. 기각.
- **G. evaluator 판정 인용 의무(기계)** — collector/evaluator 실행 자체가 산문 계약인데
  그 산출물 인용만 기계로 강제하면 "지어낸 인용"을 유도한다(검증 대상 없는 강제). 검수
  항목으로만 둔다. 기각.

## 6. 결정 ④ — 조사 실행 배선 (전부 산문 계약 — 공시)

### ⑥-1 파이프라인 (SKILL Phase 2 확장)

```
오케스트레이터 (Phase 2 진입 시):
  1. 조사 필요 판단 — 요청·clarifier 결과 기준. 판단 기준(산문):
     외부 세계에 선례·경쟁 구현·공개된 실패 사례가 있을 법한 설계 결정이 걸려 있는가
  2. 필요 판단 시: research-collector dispatch(주제 = 이번 작업 요약 + 인접 도메인 지시)
     → research-evaluator dispatch → 평가 통과분을 architect·planner 프롬프트에 주입
  3. 불요 판단 시: 불요 사유를 dispatch 프롬프트에 명시 — 작성자가 그 사유를 승계하거나
     자기 판단으로 뒤집어 "조사 필요" 를 반환할 수 있다
architect·planner:
  - 주입된 조사가 있으면: 둘째 줄 조사함(<대상·출처 — [rc]/[re] 산출물 경로 포함>) +
    본문에 반영. 조사가 없는데 필요하다고 판단하면: "레퍼런스 조사 필요: <주제>" 반환 →
    오케스트레이터가 2를 수행 후 재dispatch ("planner 직행 권고"·"clarifier 회부"와 같은
    반환 경로 부류)
  - 불요면: 둘째 줄 불요(<사유>) — 사유는 주입된 것의 승계든 자기 판단이든 명시
```

**인접 도메인 계약(조사 지시문에 상수로 포함):** *"대상 도메인과 정확히 일치하는 사례만
찾지 마라. 인접 도메인 — 같은 문제를 다른 제약에서 푼 시스템 — 을 포함하라. 우리가
라이브 스트리밍이면 VOD·저장·CDN 도 본다. 실증: pokeclip 사이드카의 답은 '라이브가 아닌
Netflix'를 제외했으면 못 찾았다(Netflix Live Origin, 2025-12)."*

**왜 실행 주체가 오케스트레이터인가:** `ecc:architect`·`ecc:planner` 는 Read·Grep·Glob
만 가진 참조 에이전트라 웹 검색·에이전트 dispatch 를 못 한다. 조사 실행은 도구를 가진
오케스트레이터의 일이고, 판정·표명은 산출물 작성자의 일이다 — 표명이 작성자 손에 있어야
검수가 "작성자의 판단"을 심사할 수 있다.

### ⑥-2 검수 계약 — 레퍼런스 검증 3항목 (회수 검증 3항목의 짝)

plan-reviewer 점검 항목과 설계·계획 pass 의 codex 리뷰 프롬프트에 추가:

1. 레퍼런스 표명이 형식대로 있는가 (둘째 줄, 두 변형 중 하나)
2. **불요 사유가 타당한가** — 특히 인접 도메인을 좁게 잘라 불요로 넘기지 않았는가
   ("라이브가 아니라고 Netflix 를 빼는" 부류를 명시 심사)
3. 조사함이면 그 조사가 설계·계획 본문에 실제로 반영·인용됐는가 (표명만 있고 본문이
   무관하면 지어낸 조사다)

**전부 산문 계약이다** — 프롬프트에 넣었는지는 기계가 확인하지 않는다(ADR-0013 ④-⑵ 와
동일한 공시).

### ⑥-3 조사 산출물 — 이름을 규정하지 않는다 (사용자 확정 ④)

collector(`_workspace/research/01_collected.md`)·evaluator(`02_evaluated.md`)의 자체 계약이
정본이다. `_workspace/` 하위는 mark-needs-audit 의 skip 분류라 게이트·재귀·명명 계약 정합
문제가 원천적으로 없다. 표명의 `<대상·출처>` 가 그 경로를 인용하는 것으로 연결은 충분하다.
하네스 소유 이름 신설은 관측된 필요 없는 새 규약이다(관측 우선).

기각 대안: **H. `_workspace/02_research.md` 규정** — mark-needs-audit 대상 여부·듀얼리뷰
관계·리뷰 명명 계약과의 정합을 전부 새로 정해야 하고, 이득은 "이름이 예측 가능하다" 하나뿐.
기각.

## 8. 이 설계가 못 막는 것 (공시 — ADR-0015 에 그대로)

- **조사했다는 사실 자체는 기계가 못 본다.** `조사함(지어낸 출처)` 는 형식을 통과한다 —
  검수(산문·확률적)와 감사자 몫. ADR-0013 의 같은 공시의 연장
- **불요 사유의 타당성은 기계가 못 본다.** `불요(시간 없음)` 도 형식 통과 — 심사는 검수 몫
- **조사 실행(collector→evaluator)은 기계가 강제하지 않는다** — dispatch 여부·품질 전부
  산문 계약
- **`stop:retrieval` 하나로 두 표명이 함께 꺼진다** — 개별 끄기 불가(수요 관측 시 재검토)
- 삭제 우회·도구 밖 생성(`bash cat >`)·서브에이전트 직접 저장 미실측 — 기존 3.4 공시 이월
- clarifier·ADR 트리거에는 레퍼런스 표명 의무가 **없다** — 범위를 설계·계획 산출물로
  좁게 시작(새 의무 신설은 관측 우선). 새는 실측이 나오면 확장 재검토
- 표명 리터럴이 한국어다 — 결정 게이트의 커버리지 공시와 같은 부류(단, 이것은 하네스가
  소유한 계약 문자열이라 발화 언어와 무관하게 유효)
- 배포 시점 어긋남: 훅은 세션 시작 스냅샷이라, sync 직후 세션에는 구 게이트(1줄 검사)가
  돌고 새 SKILL 이 2줄을 쓴다 — 새 산출물은 구 게이트도 통과하므로 무해(1줄 검사는 2줄
  머리의 부분집합). 역방향(새 훅+구 SKILL 산출물)은 차단 후 메시지가 안내한다 —
  ADR-0013 과 같은 롤아웃
