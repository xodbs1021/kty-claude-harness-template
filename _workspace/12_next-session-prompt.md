## 2. 절대 규칙

- **커밋마다 즉시 push.** `stop:push` 게이트가 강제하지만 믿지 말고
  `git rev-list --left-right --count HEAD...origin/<브랜치>` 로 `0 0` 을 눈으로 확인해라
- **혼자 정하지 마라.** 이제 결정 게이트가 기계로 막지만, 게이트는 **관찰된 한국어 표현에

## 3. **1순위 — 지식 회수 정책 (ADR-0010 재작성)**

인계의 본 과제다. 앞 세션이 결정 게이트를 만드느라 여기까지 못 왔다.

지금 상태: **배관은 깔렸고 정책은 없다.**
- 프로필 9절 "지식 진입점" 슬롯 = 경로 하나
- `ecc:architect`·`ecc:planner` 에 주입, 산출물 첫 줄에 `사전 결정 회수: <경로>`
- 그게 전부다. **무엇을 언제 어떻게 꺼내올지는 아무것도 안 정했다**

kty 가 물은 것이 정확히 이것이다 — *"harness 가 꺼내올 때 어떤 기준을 가지고, 어떤 상황에서
어떤 로직을 발동해서 꺼내올 것인가에 대한 설계는 한 거야?"*

### 답해야 할 것 넷 (ADR-0010 에 공백으로 적혀 있다)

**① 기점 — 언제 회수를 발동하나.** 지금은 착수 전 1회, 두 에이전트뿐이다. 후보:
`clarifier` 단계 · `developer` 가 구현 중 "이 부분 전에 어떻게 정했더라" 하는 순간(**실제로
더 잦다**) · 검수자가 과거 결정과의 충돌을 볼 때 · **새 결정을 내리려는 순간**(같은 결정을
다시 내리는 것을 막는 자리 — 가장 값질 수 있다).
각 후보에 *"여기서 회수하면 무엇이 달라지나"* 와 *"토큰을 쓸 값을 하나"* 를 적어라.

**② 선택 — 결정이 100건이면 무엇을 읽나.** 지금은 진입점 하나 주고 "알아서 읽어라"다.
품질은 전적으로 저쪽 라우팅 맵(볼트 `Projects/<name>/index.md`)에 달렸고 하네스는 아무 보장도
안 한다. **여기가 층 경계와 정면으로 부딪히는 자리다** — 선택 기준을 가지려면 진입점 너머를
알아야 하는데 그건 ADR-0006 위반이고, 안 가지면 품질을 보장할 수 없다. 후보:
- 상위 층이 **회수 인터페이스**를 제공하고 하네스는 그것만 호출(진입점이 "질의 → 경로 목록"을
  답하는 규약). 층은 지켜지지만 상위 층에 요구가 생긴다
- 하네스는 계속 모르고 **품질 보장 없음을 공시**한 채 둔다(현재 상태)
- 중간 — 하네스는 "무엇을 찾는지"만 전달하고 선택은 상위 층이 한다

**③ 표명을 강제로 올릴 수 있나.** `사전 결정 회수:` 는 존재·형식만 검증된다. 진짜 읽었는지는
기계가 못 본다. 올리려면 하네스가 그 경로의 **내용**을 알아야 하는데 그것도 층 위반이다.
**이 긴장도 풀거나, 못 푼다고 적어라.**

**④ `claude-mem` 과의 분업.** 회수 경로가 둘인데 규정이 없다. 하나는 압축된 세션 히스토리,
하나는 큐레이션된 결정 기록이라 성격이 다른데 그 차이가 어디에도 안 적혀 있다.

### 이월된 결정 (ADR 에 반영할 것)

- **주소 / 트리거 / 선택을 갈라 적어라.** 지금 문서는 셋을 섞어 쓴다
- **"공개 포맷 의존은 층 위반이 아니다. 사유화된 배치 의존이 위반이다"**
- **C안(`harness.env` 에 결정 경로 슬롯) 기각 사유** — 볼트 `canon-path` 를 볼트 CI 가 이미
  검증하므로 중복이고, 사용자가 패턴 목록을 유지보수하게 만들어 자동화 목적에 역행한다
- **상위 층 CI 가 보장하는 3가지**(링크 무결성·인덱스 완전성·canon 포인터)를 **전제**로 삼아라
- **남은 공백:** 타입별 frontmatter 스키마 미정의. `status` 59%·`related-projects` 27% 누락인데
  대부분 "해당 없음"이라 필터를 못 짠다. 이게 ②의 실질 제약이다

### 앞 세션이 새로 얻은 판단 기준 — 이 설계에 그대로 쓸 것

ADR-0012 ⑤·⑥절이 **"무엇을 기계로 강제하고 무엇을 단순하게 둘 것인가"** 를 처음 명시했다:

> 게이트를 기계로 두는 이유는 **판단이 못 미더워서**다. 그런데 *범위*를 정교하게 깎는 것은
> 게이트를 강하게 만들지 않는다 — 시끄럽고 비싸질 뿐이다. **버그는 고치고, 정교함은 참는다.**

회수 정책에도 같은 물음을 적용해라: 지금 없는 것이 **판단의 실패**인가(→ 기계), 아니면
**범위의 문제**인가(→ 단순하게). 그리고 **임의의 숫자·목록을 지어내야 하는 설계는 의심해라** —
kty 가 어휘 목록에 대해 지적한 것이 정확히 그것이다(*"어차피 LLM 이 정리해서 쓴 것"*).

### 산출물

- ADR-0010 을 **proposed → accepted 로 재작성**(또는 새 번호로 분리하고 0010 을 superseded 로).
  어느 쪽이 맞는지 판단해 **사유를 적어라**
- 정책이 배선을 요구하면 그 구현도(프로필 슬롯 확장 · 오케스트레이터 dispatch 계약 · 에이전트 정의)

## 5. **3순위 — `harness.env` 편집 검증 훅**

문법을 좁힌 대가로, 잘못 쓰면 **조용히 검사가 생략되고** 완료 게이트가 설 때에야 안다.

```
PostToolUse(Edit|Write) 가 harness.env 편집을 감지
  → 알려진 키를 **실제 판독기로** 읽어본다 (규칙의 사본을 만들지 마라)
  → 값을 못 믿는 키가 있으면 systemMessage 로 즉시 알린다
```

**함정 하나가 있다:** `harness_env_value` 는 "키 없음"과 "문법 밖"을 **둘 다 rc=1** 로 낸다.
그대로 쓰면 키를 안 쓴 정상 설정에도 경고가 뜬다. 판독기에 사유를 구별하는 출구를 내거나,
"판독기가 지금 이렇게 읽는다"를 표로 보여주는 쪽이 낫다 — **어느 쪽이든 규칙의 사본을 만들지
마라.** 앞 세션이 이 지점에서 멈추고 넘겼다.

## 9. 앞 세션이 실제로 당한 함정 (전부 실측 — 같은 데 빠지지 마라)

1. **변이가 남은 트리를 배포했다.** 검수 에이전트가 변이 하네스를 돌리는 중이었고 내 `cp` 에는
   dirty 검사가 없었다. 해시를 비교했는데도 못 봤다 — **둘 다 변이본이었으니까.**
   드러난 건 결과를 실측했기 때문이다. → 배포 전 `pgrep -f mutate-` 와 `git status` 를 봐라
2. **테스트 하네스에 격리가 아예 없었다.** `p="$(new_project)"` 가 **명령 치환 = 서브셸**이라
   카운터 증가가 부모로 안 돌아왔고, 모든 케이스가 디렉터리 하나를 공유했다. `mktemp -d` 로 고쳤다
3. **"방어가 서로를 가린다"를 세 번 만났다** — 판정 **순서**가 가리고, 데이터 **중복**이 가리고,
   **새 방어가 옛 방어**를 가렸다. 셋 다 통과 개수로는 원리적으로 안 보이고 변이로만 드러난다.
   그리고 변이만 넣고 케이스를 안 넣으면 초록으로 남는다(3건 그랬다)
4. **리뷰어가 조용히 죽는다.** `[cc]` 1라운드가 35분 무진전으로 스톨했다. 완료 알림이 없다고
   살아 있다고 넘겨짚지 말고 **출력 파일 mtime** 을 봐라. 되살리기보다 **짧게 쪼개 새로** 보내라
5. **선택창(AskUserQuestion)이 한 번 오작동했다.** 질문 0.5초 만에 내가 쓴 보기 라벨이 그대로
   답으로 돌아왔다(다른 8건은 36초~4분 28초). **즉답으로 돌아온 답은 의심해라.** 중요한 갈림은
   채팅으로 묻는 편이 안전하다
6. **대화 기록의 타임스탬프는 UTC 다.** KST 로 보여줄 땐 +9 하고 **단위를 명시해라**
   (앞 세션이 UTC 를 그대로 보여줘 "그 시간에 일한 적 없다"는 정당한 항의를 받았다)
7. **한글이 전송·저장 과정에서 깨진 사례가 있었다**(`훨씬`→`훨쥍`, `뺀다`→`뻐람`).
   내 오타로 오인하고 사과했다가 정정했다. 기록에 깨진 글자가 보이면 그 계통을 의심해라
8. **좁히는 수정은 한 층만 고치면 다른 층에 남는다.** 거짓 공시를 훅 주석에서 좁힌 뒤에도
   README·안내서에 넓은 판본이 살아 있었고 PR 점검이 그것을 잡았다. **고칠 때 그 주장이 적힌
   자리를 전부 세어라**
