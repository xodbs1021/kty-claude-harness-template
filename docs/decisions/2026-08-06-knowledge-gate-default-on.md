# ADR-0008: 지식 게이트는 기본 켜짐 — 표명이 없으면 이전 동작을 보존한다

**Date**: 2026-08-06 (구현·정정 2026-08-10)
**Status**: accepted
**Deciders**: 김태윤(요구 확정), Claude(설계·실측)

---

## Context

[ADR-0006](2026-08-05-knowledge-store-layer-boundary.md)이 지식 반영 게이트를 껐다 켤 수 있게 만들라고 했다. **스위치를 어디에 두고 어떻게 읽을지**가 이 ADR이다.

두 질문이 걸려 있다.

### 질문 1 — 1비트를 얻으려고 사용자 소유 셸 파일을 실행해도 되나

슬롯은 `harness.env` 다. 확장자와 문법이 셸이니 처음 설계는 그 파일을 **`source` 해서** 값을 읽었다. 그런데 막을 때마다 새 탈출 경로가 나왔다. 전부 실측이다:

| 파일에 넣은 것 | 결과 |
|---|---|
| `exit 1` | 훅이 rc=1 로 죽는다 → 완료 게이트 4종이 통째로 소멸 |
| `exit 0` | 훅이 조용히 rc=0 → 게이트 소멸 + **흔적 0** |
| 서브셸로 감싸자 `return` | 호출 셸로 정상 복귀해 판정을 통과 |
| 리다이렉트로 막자 `printf` 재정의 | 진단 출력 자체를 위조 |

이건 악의를 가정한 위협 모델이 아니다. 사용자가 실수로 `exit` 한 줄을 남기거나 다른 도구가 그 파일에 무언가를 덧붙이기만 해도 **게이트가 흔적 없이 사라진다.**

### 질문 2 — 키가 없을 때 어느 쪽으로 읽어야 하나

기존 설치본의 `harness.env` 에는 이 키가 **아예 없다.** 없을 때를 "꺼짐"으로 읽으면 하네스를 갱신하는 순간 게이트가 조용히 꺼진다.

## Decision

**① 게이트 값은 실행하지 않는다. 원문으로 읽는다.**

1비트에 임의 코드 실행의 위험을 질 이유가 없다. 실행하지 않으면 위 부류가 **원리적으로** 소멸한다 — 판독 결과를 바꾸는 유일한 방법이 "그 키를 다르게 쓰는 것"이 되고, 그게 정확히 의도적으로 값을 바꾸는 방법이다.

**② 판독 모델: 선행 공백 없는 최상위 선언이 정확히 1개일 때만 그 값을 믿는다.**

조건문·함수 본문 안의 대입은 실행돼야 발효하는데 이 파일은 실행되지 않으므로, 원문만으로는 발효 여부를 알 수 없다. 선언이 2개 이상이면 어느 것이 이기는지도 알 수 없다.

**③ 끄는 방법은 값을 리터럴로 비우는 것 하나뿐. 그 외는 전부 켜짐.**

키가 없어도 · 선언이 2개여도 · 지원 문법 밖이어도 **켠다.** 업그레이드가 게이트를 조용히 끄는 것이 이 설계에서 가장 나쁜 결과이기 때문이다. 사용자는 지식이 쌓인다고 믿는데 그 턴부터 아무것도 안 남고, 아무 에러도 안 난다.

`sync.sh` 는 키가 없는 설치본에 `HARNESS_KNOWLEDGE_GATE="on"` 을 **덧붙이기만** 한다 — 동작은 어차피 같지만, 파일에 한 줄도 없으면 사용자가 그런 스위치가 있다는 것 자체를 모른다.

**④ 실행을 버리면 셸 파서 의무를 물려받는다 (2026-08-10 정정).**

원래 설계는 여기까지였고, 그것이 부족했다. `source` 를 버린 뒤 파싱을 절반만 해서 **fail-open 을 없애려다 다른 fail-open 6종**을 만들었다. 값에 쓰레기가 섞여 `sh -c` 가 rc=127 을 내고, 호출부가 그걸 "도구가 없구나"로 읽어 검사를 조용히 생략한다:

| 입력 | 실행했다면 | 절반만 판독하면 |
|---|---|---|
| `KEY="cmd" # 메모` | `cmd` | `"cmd" # 메모` 전체 → rc=127 |
| `KEY="cmd"` + 후행 공백 | `cmd` | `"cmd"   ` → rc=127 · **눈에 안 보인다** |
| CRLF 줄끝 | `cmd` | `"cmd"\r` → rc=127 · **눈에 안 보인다** |
| 파일 앞 BOM | 무해 | 첫 키가 **무매치** → 미설정 |
| 히어독 본문의 같은 키 | 선언 아님 | **선언으로 셈** → "2개" 판정 |

그래서 판독 순서를 계약으로 고정한다:

```
① BOM 제거 → ② CR 제거 → ③ 히어독 본문 배제 → ④ 선언 판정
→ ⑤ 값 앞 공백 절단 → ⑥ 따옴표 벗기기 → ⑦ 따옴표 밖 후행 주석 → ⑧ 남은 후행 공백 절단
```

그리고 **지원 문법을 좁게 고정하고 문서에 적는다.** 사용자는 "셸 파일이니 셸 문법이 다 되겠지"라고 가정하기 때문이다. 문법 밖은 조용히 절반만 읽지 않고 전부 "값을 믿을 수 없음"으로 떨어진다.

**⑤ "리터럴로 비웠다"와 "값을 믿을 수 없다"를 반환 코드로 가른다.**

스위치형 슬롯에서 이 둘은 **반대 방향**이다(전자는 끄고, 후자는 켠다). 빈 문자열 하나로 뭉뚱그리면 사용자가 일부러 끈 것과 키가 없는 기존 설치본이 구별되지 않는다.

## Alternatives Considered

### A. `source` 하되 서브셸·리다이렉트로 가둔다
- **Pros**: 셸 문법을 공짜로 얻는다. 파서를 직접 쓰지 않아도 된다
- **Cons**: 막을 때마다 새 탈출 경로가 나왔다(위 표). 서브셸로 막으니 `return`, 리다이렉트로 막으니 `printf` 재정의
- **Why not**: 창을 좁히는 접근이라 끝이 없다. **부류를 없애야** 멈춘다

### B. 값을 JSON·INI 등 비실행 형식으로 바꾼다
- **Pros**: 파싱 계약이 명확하고 셸 파서 의무를 안 물려받는다
- **Cons**: 기존 설치본의 `harness.env` 를 전부 마이그레이션해야 하는데, 슬롯은 프로젝트 소유라 하네스가 덮을 수 없어 강제할 수단이 없다
- **Why not**: 이행 비용이 얻는 것보다 크다. 지원 문법을 좁혀 문서화하는 것으로 같은 안전성에 도달한다

### C. 키가 없으면 꺼짐 (관용구 일관성)
- **Pros**: `HARNESS_TYPECHECK_CMD` 의 "비우면 생략" 과 모양이 같다
- **Cons**: 기존 설치본에는 키가 없다 → **업그레이드가 게이트를 조용히 끈다**
- **Why not**: 관용구 일관성보다 동작 보존이 무겁다. 조용히 꺼지는 게이트는 없는 것만 못하다

### D. `="off"` 도 꺼짐으로 인정한다
- **Pros**: 직관적이다. `off` 라고 적으면 꺼지리라 기대하는 것이 자연스럽다
- **Cons**: "리터럴로 비었을 때만 끈다"는 단일 규칙이 깨지고, 그 다음엔 `false`·`0`·`no`·`OFF` 를 어디까지 인정할지가 끝없이 이어진다. 인정 목록에서 빠진 표기를 쓰면 **사용자는 껐다고 믿는데 켜져 있다**
- **Why not**: 규칙을 하나로 유지하고, 대신 그 직관 충돌을 **세 곳에 명시**한다(`harness.env` 주석 · `docs/usage.md` · 오케스트레이터 스킬)

## Consequences

### Positive
- 임의 코드 실행 부류가 원리적으로 소멸
- 업그레이드가 게이트를 조용히 끄는 경로가 없다
- 실패 방향이 전부 "켜짐" 쪽이다 — 판독이 어떻게 틀려도 게이트는 살아 있다

### Negative
- **셸 파서 의무를 물려받았다.** 지원 문법이 좁고, 그 사실을 사용자가 알아야 한다
- `="off"` 가 켜짐으로 읽히는 것은 직관에 반한다. 문서로만 완화된다
- 히어독 탐지는 근사다. 한 줄에 히어독이 둘이면 첫 개만 본다

### 실패 방향이 왜 안전한가
히어독 탐지가 어느 쪽으로 틀려도 결과는 "값을 믿을 수 없음"으로 수렴한다 — 히어독을 놓치면 선언이 2개가 되고, 없는 히어독을 만들면 0개가 된다. 둘 다 게이트는 **켜짐**이다.

## 기계적 장치

`tests/harness-env-read.test.sh` 가 판독 계약(반환 코드 + 값의 바이트)과 게이트 계약을 붙든다.

게이트 케이스는 `harness.env` 의 키 개수와 값을 **직접 해석하지 않는다.** 지식 플래그 하나만 세우고 **훅 자신을 돌려** 차단되는지를 본다 — 판독 규칙의 사본을 테스트에 두면 그 사본이 언젠가 원본과 어긋나고, 그때 테스트는 **틀린 기준으로 초록**을 낸다.

통합 케이스는 종료 코드만 보지 않는다. 타입체크를 건너뛰어도 뒤의 감사 게이트가 어차피 rc=2 로 막으므로, **어느 게이트가 막았는지의 문구**까지 재야 판별력이 생긴다.
