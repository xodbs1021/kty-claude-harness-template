## Context

완료 게이트 플래그를 세우는 `mark-needs-audit.sh` 는 세션 루트(그 세션의 첫 훅
호출이 고정한 프로젝트 루트 — PR #50) 밖 파일을 **파일 정체성**으로
분류한다(ADR-0007). 밖이면 하네스 정본 저장소이거나 `.claude/` 에 앵커된 하네스
경로일 때만 게이트를 세우고, 나머지는 건너뛴다.

그래서 **세션 루트 밖 다른 저장소를 고치는 세션에는 게이트가 하나도 서지
않았다.** 2026-10-12 실측(가짜 세션 입력으로 훅을 직접 호출): 세션 루트(git
저장소 아님) 안 파일은 플래그 4종, 세션 루트 밖 상류 프로젝트 clone 의 Go 파일은
플래그가 0 이었다. 입력 cwd 를 clone 으로 줘도 0 이었다 — 세션 루트는 첫 호출에
고정된다. 그 프로젝트의 작업은 전부 그런 clone 들에서 일어나므로, 리뷰 · 변경
설명 · 지식 · 감사 게이트 없이 다른 저장소의 코드가 바뀐다.

같은 저장소의 다른 체크아웃은 PR #50 이 잡았다. 다른 저장소는 위치로 추측할 수
없다 — 남의 저장소를 잠깐 고쳐도 게이트 4종이 서면 탈출구를 상시로 쓰게 되고
게이트가 무력해진다(ADR-0007 대안 B).

kty 가 정했다.

*   템플릿에 슬롯을 새로 둔다. 트랙마다 clone 안에서 세션을 열고 clone 마다
    설치하는 대안은 기각했다.
*   트랙 작업 공간(저장소 옆 `_workspace_<저장소>/`)은 그대로 두고, 그 리뷰
    산출물로 듀얼리뷰가 풀리게 한다.
*   슬롯 저장소에는 플래그 4종만 건다 — 타입체크 · 스타일 · push · 커밋 가드는
    걸지 않는다.
*   리뷰 파일 이름 규약은 `*codex*.md` 하나다.
*   하위 호환(키가 없거나 비면 출력 바이트가 같다)은 harness.env 를 정상으로
    읽을 수 있을 때 적용한다. 깨졌거나 읽을 수 없으면 슬롯 상태를 알 수 없으므로
    알린다.
*   같은 값의 병렬 판정 사이에 소속이 바뀌는 틈(아래 Negative)은 고치지 않고
    공시한다(설계 게이트 종결, 2026-10-12).

## Decision

세션 루트 밖 저장소의 편집도 게이트로 잡되, 어느 저장소인지는 **사용자가
harness.env 에 선언한 폴더 하나**로만 정한다. 이 폴더를 슬롯(추가 관할 폴더)이라
부른다. 슬롯 안 저장소의 듀얼리뷰 의무는 그 의무를 마지막으로 쓴 판정이 기록한
**리뷰 자리**에서만 풀린다.

### 1. 키 — 폴더 하나, 옵트인

*   키는 `HARNESS_EXTRA_GATE_DIRS` 하나이고 값은 폴더 하나다(목록이 아니다). 키
    이름의 유일 지점은 `_common.sh` 의 `EXTRA_GATE_KEY` 다.
*   값은 절대경로나 `~/` 로 시작한다. 따옴표 안의 `~` 도 펼친다. 쓸 수 없는 값과
    사유 코드: `:` 가 든 값(colon) · `~사용자` 이거나 홈을 모름(tilde) ·
    비절대(relative) · 없거나 들어갈 수 없는 폴더(missing) · 물리 경로에
    개행(newline) · 물리화한 결과가 `/`(root).
*   판독은 기존 판독기 그대로다(실행하지 않는다 — ADR-0016).
    `extra_gate_key_state` 가 상태를 셋으로 가른다.
    *   VALUE — 값이 있다.
    *   UNTRUSTED — 판독기가 값을 믿을 수 없다고 했거나(rc 1), 키가 없다는데
        harness.env 자리가 읽을 수 없는 꼴이다(폴더 · 끊긴 심링크 · 탐색할 수
        없는 폴더 아래).
    *   ABSENT — 정상 파일에 키가 없거나 값이 비었다. 파일이 없고 가장 가까운
        존재 조상이 탐색 가능한 폴더여도 ABSENT 다.
*   키를 쓸 수 없으면 슬롯은 꺼지고 그 사실을 알린다. 편집 검증
    훅(check-harness-env)은 그 자리에서, 완료 게이트 훅(mark-needs-audit)은
    세션마다 같은 사유당 한 번 알린다(표식 `.extra-gate-notice`). 사유 문구는
    `_common.sh` 의 `extra_problem_text` 에 있어 모듈이 없어도 나간다.
*   ABSENT 면 판독 1회와 셸 내장 검사 말고는 아무것도 하지 않는다.

### 2. 판정 — ⑤′ 추가 관할 폴더 저장소

*   `verdict_of` 의 순서가 계약이다: ① 같은 저장소의 다른 체크아웃 ② 세션 루트
    안 ③ 밖 + 하네스 정본 저장소 ④ 밖 + `.claude/` 앵커 ⑤′ 밖 + 추가 관할 폴더
    저장소 ⑥ 그 밖은 건너뜀.
*   ⑤′ 는 슬롯이 켜졌고, 값이 슬롯 항목이고(절대경로 · 세션 루트 밖 · 슬롯 안 —
    `is_slot_entry`), 그 파일의 git 최상위가 슬롯 안일 때다. 그 최상위를
    기준으로 기존 `classify` 가 나눈다 — 폴더 안에서 무엇을 검사할지는 기존 규칙
    그대로다.
*   ⑤′ 는 ④ 뒤에만 둔다. 앞에 두면 슬롯 저장소의 `.claude/` 앵커 파일을
    `classify` 가 `.claude/*` 로 빼서 조용히 사라진다(ADR-0007 의 "판정 순서가
    곧 계약").
*   폴더째 지운 파일은 가장 가까운 존재 조상에서 git 최상위를 찾는다. "같은
    폴더인가"는 표기가 아니라 같은 파일 판정(`-ef`)으로 본다 — 대소문자 · NFD
    표기 차이로 슬롯이 조용히 꺼지지 않게.
*   설계 · 계획 산출물: 기존 글롭에 더해, 슬롯 항목이고 부모 폴더 이름이
    `_workspace` 또는 `_workspace_*` 이고 파일 이름이 `NN_design*.md` ·
    `NN_plan*.md` 이면 듀얼리뷰 · 지식 · 머리 표명 3종을
    세운다(`is_design_shaped`).
*   세션 루트 안 판정은 바뀌지 않는다 — 슬롯 항목은 세션 루트 밖으로만 정의된다.

### 3. 리뷰 자리 기록과 수명 계약

듀얼리뷰 의무를 쓰는 판정은 그 의무를 풀 자리를 세션 상태 폴더의 `.review-dirs`
에 덧붙인다(슬롯이 켜졌고 값이 절대경로일 때만). 형식의 정본은
`_extra_gate_dirs.sh` 의 머리 주석이다. 훅들은 형식을 모르고 rc · 사유 코드 ·
`W`/`M` 줄만 안다.

*   **형식:** 한 줄 = `값 US 꼬리`(US = 0x1F, 값 = 듀얼리뷰 플래그에 적힌
    절대경로). 꼬리는 셋 중 하나다 — `-`(빈 집합: 세션 루트 규칙) · `!`(갱신
    표시: 의무 갱신이 시작됐고 현재 기록이 아직 없다) · `/자리[US/자리…]`(리뷰
    자리).
*   **값마다 마지막 줄이 현재 기록이다.** 덧붙이기만 하고 대체 쓰기 · 잠금은
    없다. 맨 `값`(꼬리 없음)은 쓰지 않는다.
*   **모르는 꼴은 막는 쪽으로 읽는다:** 꼬리 없음 · 빈 필드 · `/` 로 시작하지
    않는 필드 · `-`·`!` 가 섞인 꼬리 · 개행 없이 끝난 마지막 줄(덧붙이기가
    잘렸다)은 missing-record 다.
*   **자리 규칙:** 슬롯 항목인 설계물 → 그 파일의 폴더. 슬롯 항목이고 분류 기준
    저장소가 슬롯 안 → 그 저장소의 `_workspace/` 와 옆 `_workspace_<저장소>/`
    둘(④ 앵커여도 같다). 그 밖(git 밖 앵커 · 최상위가 슬롯 밖 · 슬롯 밖 절대
    항목) → 빈 집합. 슬롯 항목인데 조상에 `.git` 이 있으면서 git 이 최상위를
    돌려주지 못하면(소속 모름) 현재 기록을 쓰지 않는다 — 끝줄이 갱신 표시로 남아
    막힌다.
*   **수명 계약(결속 순서):** 한 판정 안에서 ① 갱신 표시 `값␟!` → ② 듀얼리뷰
    플래그 갱신 → ③ 현재 기록을 이 순서로 쓴다. ③ 만 실패하는 경로는 막힌다 —
    끝줄이 갱신 표시라 Stop 이 missing-record 로 본다. ② 가 실제로 갱신되지
    않았으면 ③ 을 쓰지 않는다. 자리는 그 판정 시점의 소속으로 계산한다 — 다시
    고치면 새 소속을 따른다.
*   **한 줄 1023바이트 상한:** bash 3.2 의 printf 는 그보다 긴 줄을 1024바이트씩
    나눠 써서, 병렬 덧붙이기가 그 사이에 끼면 줄이 섞여 다른 값 · 자리로 읽힌다.
    넘는 줄은 쓰지 않는다(영구 실패).
*   **기록 실패는 저장 때 알린다**(PostToolUse 는 막지 않는다): 회복 가능은
    `MSG_RECORD_FAIL`(세션 폴더 쓰기 · 기록 파일 종류), 영구는
    `MSG_RECORD_PERMANENT`(경로에 US · LF, 줄 1023바이트 초과), 슬롯 안
    `.claude/` 앵커 저장소의 git 판독 실패는 `MSG_RECORD_GIT` 이다(슬롯 갈래만 —
    일반 갈래의 `MSG_GIT_UNAVAILABLE` 은 그대로). 셋 다 Bash 스윕에서도 스윕
    집계 알림(`MSG_SWEEP_PARTIAL` 등)으로 접히지 않고 따로 나간다. 갱신 표시부터
    기록할 수 없는 값(US · LF, 갱신 표시 줄 1023바이트 초과)이 git 판독도
    실패하면 영구 문구만 낸다 — git 을 고쳐 다시 저장해도 그 값은 기록되지
    않는다. 현재 기록 줄만 1023바이트를 넘는 값은 git 이 실패한 때 자리를 몰라
    알 수 없어 `MSG_RECORD_GIT` 을 내고(문구가 그 경우를 함께 적는다), git 을
    고쳐 다시 저장할 때 영구 문구가 나간다(2단계, 시험 v26).

### 4. 완료 게이트(Stop) 3.5 — 결정 표

| 키 상태 | 기록 파일 | 평가(서브셸) | 3.5 동작 |
|---|---|---|---|
| ABSENT | 무관 | 안 함 | 기존 루프 원문 — 세션 루트 `_workspace/*codex*.md`(출력 바이트 같음) |
| UNTRUSTED | 없음 | 안 함 | 기존 루프 |
| UNTRUSTED | 있음 | rc 0 / 3 | 해제 / 막음 — 슬롯 폴더를 몰라 기록 없는 절대 항목은 세션 루트 규칙(dir-unknown) |
| VALUE | 무관(없으면 0줄) | rc 0 / 3 | 해제 / 막음 — missing-record · unrecordable |
| UNTRUSTED · VALUE | (평가한 경우) | rc 4 | 기록 파일과 무관하게 막음 — record-unusable · root-unusable(세션 루트에 개행 · US) |
| UNTRUSTED · VALUE | (평가한 경우) | 그 밖(모듈 없음 9 · 환경 장애 5 · 신호 종료 128 이상 · 사망 · 판독 실패) | 기록 파일이 있으면(0바이트 포함) 막음 — module · eval-env · eval-signal · eval-fail. 없으면 기존 루프 |

*   **평가**(`read_review_verdict <물리 세션 루트>`)는 플래그 항목마다 그 값의
    마지막 기록 줄로 본다.
    *   자리 줄 → 자리 중 한 곳에 플래그보다 새, 비지 않은 일반 파일
        `*codex*.md` 가 있으면 충족.
    *   빈 집합 줄 · 기록 없는 상대 항목 → 세션 루트 `_workspace` 에서 같은
        조건.
    *   갱신 표시 · 모르는 꼴 → missing-record.
    *   기록 없는 절대 항목 → 슬롯을 알고 슬롯 항목이면 missing-record(값에 US
        면 unrecordable), 아니면 세션 루트 규칙(슬롯을 모르면 사유 dir-unknown).
*   기록 파일이 없으면 0줄로 평가한다. 있으면 일반 파일 · 읽기 · 쓰기가 가능해야
    한다 — 아니면 record-unusable(rc 4). 결과를 바꾸는 검사는 쓰기 가능(`-w`)과
    일반 파일(`-f`)이고, 읽기(`-r`)는 사유 문구를 정밀화한다. 세션 루트 경로에
    개행 · US 가 있으면 판정하지 않고 root-unusable(rc 4)로 막는다.
*   평가할 수 없을 때(모듈 없음 · 사망 · 판독 실패) 증거는 **기록 파일의
    존재**다. Stop 은 기록 줄을 해석하지 않는다. 기록 파일은 슬롯이 켜진 판정만
    만든다.
*   평가는 서브셸에서 한다 — 모듈이 죽어도 본 셸은 끝나지 않는다. 모듈을 읽지
    못하면 서브셸이 rc 9 로 알린다(module). 판독기 awk 가 돌지 못하거나 히어독
    임시 파일을 만들거나 쓰지 못하면 모듈이 rc 5 로 알린다(eval-env — 환경
    장애라 다시 설치로 풀리지 않아 사용자 판단을 안내한다). 서브셸이 신호로
    죽으면(rc 128 이상 — 예: bash 3.2 에서 파일 크기 한도 아래 히어독 쓰기가
    SIGXFSZ 로 서브셸을 죽인다, rc 153) 모듈은 rc 를 내지 못하고 Stop 은 원인을
    가릴 수 없다(eval-signal — rc 를 싣고, 모듈이 바뀌었거나 망가졌으면 sync 로
    풀리지만 자원 한도 같은 환경 원인이면 다시 설치로 풀리지 않는다고 함께 말해
    사용자 판단을 안내한다). 그 밖의 rc 는 모듈 오류다(eval-fail — sync).
*   해제는 모든 항목이 충족될 때만이고, 그때 플래그 전체를 지운다.
*   **막음 안내**는 기다리는 자리(`W`) · 현재 기록이 없는 값(`M`) · 사유를
    나열하고 실제 해제 조건만 말한다. 평가 첫 줄의 슬롯 상태(on · untrusted ·
    invalid)로 missing-record 와 dir-unknown 의 문구를 가른다 — 슬롯이 꺼져
    있었으면 값 검증 실패(invalid)는 "harness.env 슬롯 설정을 고친 뒤", 판독
    불가(untrusted — 슬롯 키든 다른 키든 문법이 깨짐)는 "harness.env 를 정상으로
    읽을 수 있게 고친 뒤" 그 파일을 다시 저장하라다(그 값의 기록 줄이
    1023바이트를 넘으면 그렇게 한 뒤의 Stop 이 켜짐 문구로 영구임을 알린다).
    사유가 없고 남은 자리가 세션 루트 `_workspace` 하나뿐이면 기존 막음 안내를
    낸다(`DR_MODE=root`). 큰 본문에서도 나열이 빠지지 않게 목록은 입력을
    끝까지 읽어 한 번 만든다.
*   막힘의 기존 출구 — 같은 지점 3회 차단 뒤 경고와 함께 통과(`MAX_BLOCKS`),
    사용자 전용 탈출구 — 는 그대로다.

### 5. 발행 게이트 ②

*   기록 파일이 있고 키 상태가 ABSENT 가 아니면(UNTRUSTED 포함) "최근 리뷰"를
    세션 루트 `_workspace` 와 기록된 리뷰 자리에서 함께 찾는다. 창(기본 180분)
    기준은 그대로다(ADR-0022).
*   기록을 읽지 못하면(모듈 유실 · 오류, 기록 파일 종류 · 권한, 기록 판독기
    awk 의 환경 장애 · 자원 한도) 세션 루트만 본다(거부 쪽). 그래도 세션 루트
    리뷰로 통과하면 그 사실을 `systemMessage` 로 알린다.
*   안내 문구는 슬롯 모드에서만 바뀐다 — 슬롯 리뷰 자리는 기록에서 자리를 하나라도
    읽었을 때만 덧붙인다. 예외는 ① 의 저장 안내다: 기록 파일이 없어도 키에 값이
    있으면 항목별 자리 안내를 낸다 — 그때도 Stop 은 슬롯 판정으로 막는다(세션 중에
    키를 켬 · 첫 값이 기록 불가). 키가 없으면 기존 바이트다.

### 6. Bash 스윕 — 슬롯이 켜졌을 때만

*   뿌리(훑기 시작 폴더)를 넓힌다: cwd · 명령문 절대경로 · 홈 토큰(`~/…` — 단어
    머리의 `~` 만)이 가리키는 슬롯 저장소, 트랙 작업 공간 뿌리(`_workspace*` —
    물리화한 뒤 한 단계만, 설계 모양만), 쌍 뿌리(저장소 T ↔ 옆 `_workspace_T`).
*   명령문 토큰 뿌리는 상한 3 을 함께 쓴다. 명령문 토큰에서만 얻은 쌍 저장소는
    창 기반 find 만 하고 미커밋 삭제 판정에서 뺀다 — 읽기만 하는 명령이 다른
    트랙의 미커밋 삭제를 이 세션 의무로 올리지 않게. cwd 에서 얻은 쌍은 cwd
    저장소처럼 판정한다.
*   시간 예산 20 s 를 둔다 — Bash 훅 상한 30 s 전에 스스로 멈추고 절단을 알린다.
    뿌리 수집 단계에도 같은 예산을 건다.
*   판정은 Edit 경로와 같은 `judge_file` 이다(사본 없음). 슬롯 전체는 훑지
    않는다.

### 7. 출력 — 알림 단일 출구

*   완료 게이트 훅은 진입 뒤의 모든 종료 경로가 `finish_hook` 하나를 지난다 —
    PostToolUse stdout 은 JSON 한 줄이 계약이다. 키가 없으면 알림이 없어 출력
    바이트가 예전과 같다.

### 하지 않는 것

*   슬롯 저장소의 타입체크 · 스타일 검사 · push 확인 · 기본 브랜치 커밋
    가드(Context 의 kty 결정 — 플래그 4종만 건다).
*   다중 슬롯 · 목록 형식(대안 B), 슬롯 전체 스윕(대안 G), NotebookEdit 포착,
    리뷰 이름 규약 확장.

### `_workspace_<이름>` 형제 규약을 하네스 규약으로 올린다

저장소 T 옆의 `_workspace_<T 이름>/` 은 지금까지 운영 관례였다. 이 결정으로
하네스 규약이 된다 — 리뷰 자리 · 설계물 판정 · 스윕 쌍 추론이 모두 이 이름
규칙(`sibling_workspace_of` · `sibling_repo_of`)을 쓴다.

### 바뀐 자리

*   신설 `template/.claude/hooks/_extra_gate_dirs.sh` — 슬롯 계약 모듈(설정 ·
    소속 · 기록 쓰기 · 읽기). source 전용이다.
*   `template/.claude/hooks/_common.sh` — 키 상수 · 기록 · 표식 경로 ·
    `extra_gate_key_state` · `extra_problem_text`. 판독기는 바꾸지 않았다.
*   `template/.claude/hooks/mark-needs-audit.sh` — 진입 설정 · `finish_hook` ·
    ⑤′ · 리뷰 자리 기록 · 스윕 뿌리.
*   `template/.claude/hooks/verify-before-stop.sh` — 3.5 결정 표 · 막음 안내.
*   `template/.claude/hooks/guard-publish-review.sh` — ② 자리 확장 · 안내.
*   `template/.claude/hooks/check-harness-env.sh` — `KNOWN_KEYS` · 값 검증 ·
    관할 폴더 키 안내.
*   `template/.claude/harness/harness.env.template` — 주석 블록(키는 주석
    예시로만 둔다).
*   `template/.claude/skills/harness-orchestrator/SKILL.md` — 끼워 넣기만
    했다(기존 줄은 고치지 않았다). "듀얼 리뷰 규칙" 절의 "리뷰 산출물은 세션
    루트의 `_workspace/`에 둔다" 항목 뒤에 슬롯 리뷰 자리 항목 하나, Phase 5 의
    끝에 한 문단, Phase 6 의 첫 두 문단(완료 감사 · 훅 강제) 뒤 · 결정 게이트
    문단 앞에 한 문단.
*   `docs/usage.md` — 키 안내 · 훅 표 · "추가 관할 폴더 슬롯" 소절(운영 안내 ·
    한계). ADR-0024 의 "후속 이력"에 한 항.
*   시험 `tests/extra-gate-dirs.test.sh`(러너와 축별 케이스 파일 13개, 210
    케이스)와 CI 단계 하나. 기존 14묶음은 고치지 않았다.

## Alternatives Considered

**A. 트랙마다 clone 안에서 세션을 열고 clone 마다 하네스를 설치한다**

*   Pros: 템플릿을 고치지 않는다. clone 이 세션 루트라 기존 게이트가 그대로
    선다.
*   Cons: clone 마다 설치 · sync 가 필요하다. 트랙 작업
    공간(`_workspace_<clone>/`)은 clone 밖이라 그 설계 산출물은 여전히 세션 루트
    밖이다.
*   Why not: kty 가 기각했다(템플릿에 슬롯 신설).

**B. 키 형식을 넓힌다 — `:` 목록 · 같은 키 여러 줄 · `$HOME` 펼침 · 상대경로 ·
`/`**

*   Pros: 흩어진 폴더를 한 키로 덮는다. `:` 목록은 PATH 관용구라 문법이 스스로
    설명된다.
*   Cons: 같은 키 여러 줄(git `safe.directory` 식)은 판독기 계약(선언이 둘
    이상이면 믿을 수 없음 — ADR-0016)과 정면으로 부딪힌다. `$HOME` 은 셸이
    따옴표 종류에 따라 다르게 펼치는데 판독기는 따옴표 종류를 잃는다 — 셸 규칙의
    부분 사본이 생긴다. 상대경로는 세션 루트가 바뀌면(워크트리 세션) 같은 값이
    다른 폴더를 가리킨다. `/` 는 관할을 파일시스템 전체로 만든다.
*   Why not: kty 가 단일 경로를 정했다. 지금 필요한 폴더가 하나이고, 지금 `:` 를
    금지해 두면 나중에 목록으로 넓혀도 하위 호환이 된다. git
    `includeIf gitdir`(폴더 하나에 조건을 거는 선언)과 같은 모양이다.

**C. Claude Code 의 추가 디렉터리(`--add-dir` · `/add-dir` ·
`permissions.additionalDirectories`)를 슬롯으로 재사용한다**

*   Pros: 사용자가 이미 적는 설정을 다시 쓴다.
*   Cons: 실행 중 `/add-dir` 은 `DirectoryAdded` 를 발화하지만 시작 때의
    `--add-dir` 은 발화하지 않는다(공식 훅 문서 — 설계 리뷰 대조). settings 의
    `additionalDirectories` 가 발화하는지와 `SessionStart` 입력은 미확인이다.
    훅이 시작 목록을 다 볼 수 없으면 감시가 조용히 준다.
*   Why not: 추가 디렉터리는 접근 권한("읽고 써도 된다")이고 슬롯은 의무("고치면
    게이트가 선다")다 — 참고로 읽기만 허용한 저장소에까지 게이트가 서는 오탐이
    된다. 도구 제공자가 소유한 설정 형식에 기대게 되고, `settings.json` 은 sync
    로 덮이는 글루라 프로젝트 고유 경로를 둘 자리가 아니다(프로젝트 고유 값은
    슬롯 harness.env 에 둔다).

**D. 리뷰 자리를 다시 기록할 때 옛 줄을 바꿔 쓴다(파일 다시 쓰기)**

*   Pros: 파일이 커지지 않는다. 값마다 줄이 하나다.
*   Cons: 병렬 PostToolUse 의 읽고-고치고-쓰기가 겨뤄 다른 값의 줄이 사라진다.
    잠금이 필요하다.
*   Why not: 덧붙이기 + 값마다 마지막 줄(git config 단일 값 키 · Kafka 로그
    컴팩션과 같은 모양)이 잠금 없이 같은 것을 준다.

**E. 기록 실패를 다른 수단으로 감지한다 — 플래그 · 기록 파일의 mtime 비교, 실패
표식 파일, 실패 줄을 듀얼리뷰 플래그 파일에**

*   Pros: 기록 형식에 줄 꼴(갱신 표시)을 더하지 않는다.
*   Cons: mtime 비교 — 플래그는 다른 값의 편집으로도 갱신돼 어느 값이 낡았는지
    모르고, 다른 파일을 다시 저장하면 낡은 값을 가린 채 풀린다. bash 3.2 `-nt`
    는 초 단위라 같은 초 실패를 못 본다. 실패 표식 파일 — 같은 세션 폴더라 기록
    파일이 실패하면 그 파일도 같이 실패한다. 플래그 파일에 실패 줄 — "한 줄 =
    경로" 계약을 감사자 · 차단 문구 · 예산 나열 같은 모든 소비자에 대해 깬다.
*   Why not: 갱신 표시 줄(결속 순서 ①)은 새 파일이 아니라 같은 기록의 한 줄
    꼴이고, ③ 만 실패하는 경로를 막는다.

**F. 평가할 수 없을 때 근사 대조로 판정한다(`grep -F` 로 기록에 값이 있는지)**

*   Pros: 모듈이 유실돼도 세션 루트 항목만 남은 묶음은 풀 수 있다.
*   Cons: Stop 이 기록 형식(첫 필드) 지식을 다시 갖게 된다. 부분 문자열 · 자리
    필드 일치와 rc 혼동을 막는 정밀화가 또 장치가 된다.
*   Why not: "기록 파일의 존재 = 증거"는 장치가 없고 실패 방향이 언제나 막는
    쪽이다. 대가(모듈 유실 때의 과차단 — 출구 sync)는 Negative 에 공시했다.

**G. 슬롯 전체를 스윕한다**

*   Pros: 명령문 토큰 · cwd 에 기대지 않아 Bash 구멍이 준다.
*   Cons: 다른 트랙이 같은 시간에 쓰거나 지운 파일까지 이 세션의 의무로 올린다 —
    추측으로 남의 저장소에 게이트를 세운다.
*   Why not: 오탐 금지가 먼저다. 저장소 뿌리 · 작업 공간 뿌리 · 쌍 뿌리만 쓰고
    남는 구멍은 공시한다.

**H. 공간 부족에 대비해 덧붙이기 실패를 Stop 까지 보존한다**

*   Pros: 공간 부족 동안의 옛 줄 틈(Negative "결속의 남는 틈")을 닫는다.
*   Cons: 보존할 자리도 같은 파일시스템에 써야 한다 — 대안 E 의 실패 표식 파일과
    같은 이유로 함께 실패한다.
*   Why not: 공시를 정정하는 쪽으로 정했다(공간 부족은 일시 장애와 같은 틈이다).

## Consequences

**Positive**

*   세션 루트 밖 저장소의 편집에도 플래그 4종이, 슬롯 안 트랙 작업 공간의 설계 ·
    계획 산출물에도 3종이 선다 — 2026-10-12 실측의 "플래그 0" 이 사라진다.
*   듀얼리뷰가 그 저장소의 리뷰 자리에서 풀려, 트랙 작업 공간을 세션 루트로
    옮기지 않아도 된다.
*   키가 없으면 출력 바이트가 같다. 의도된 차이는 아래 절의 셋뿐이다.
*   기록 형식이 모듈 한 파일 뒤에 있어, 형식이 바뀌어도 Stop · 발행 게이트를
    고치지 않는다. 설계 중에 형식이 세 번 바뀐 축이다.
*   찾아낸 fail-open 경로(조용히 풀리는 경로)는 막는 쪽이나 알리는 쪽으로
    닫았다. 남은 틈은 아래에 적었다.

**Negative (못 막는 것은 못 막는다고 쓴다 — ADR-0011)**

운영 문서 `docs/usage.md` 의 "추가 관할 폴더 슬롯" 소절에 같은 목록을 운영
안내와 함께 실었다.

### 관할 범위

*   **관할 단위 밖:** 저장소의 하위 폴더만 적은 슬롯(최상위가 슬롯 밖) · 슬롯 안
    심링크가 가리키는 바깥 저장소 · 슬롯 밖에 둔 링크 워크트리는 잡지 않는다.
    `/` 는 쓸 수 없는 값이다.
*   **슬롯이 clone 하나면** 옆 `_workspace_<clone>/` 이 슬롯 밖이라 그 설계 ·
    계획 산출물에 게이트가 서지 않는다(템플릿 주석이 안내한다). 그 폴더는 여전히
    리뷰 자리로 기록돼, 사용자가 선언하지 않은 폴더의 리뷰가 해제에 인정된다 —
    짝 이름 하나로 정해지는 폴더다.
*   **슬롯 안 git 밖 파일**은 게이트가 없다. 설계 모양과 기존 `.claude/` 앵커만
    예외다.
*   **슬롯 저장소 검사는 플래그 4종뿐이다** — 타입체크 · 스타일 · push 확인 ·
    기본 브랜치 커밋 가드가 없다.
*   **세션 루트와의 관계(PR #50 대조):** PR #50 은 "한 세션 = 루트 하나. 다른
    체크아웃 파일 편집은 의무로 잡히지만 push·타입체크·리뷰 산출물 탐색은 세션
    루트에서만."을 공시했다. 슬롯은 그 가운데 리뷰 산출물 탐색만 넓힌다 — 슬롯
    항목의 듀얼리뷰 해제(Stop 3.5)와 발행 게이트 ②. 세션 루트
    고정(`bind_project_dir`의 `.root`)과 세션 상태 폴더는 그대로이고, push ·
    타입체크 · 스타일은 여전히 세션 루트에서만 본다. 다른 체크아웃 판정(①)이 ⑤′
    보다 먼저이고, 그 체크아웃이 슬롯 안이면 리뷰 자리는 그 체크아웃의
    `_workspace/` · 옆 `_workspace_<이름>/` 이다(시험 k07). 세션 루트가 슬롯 안
    저장소 자신이면 그 저장소 편집은 세션 루트 안 판정(상대경로 · 세션 루트
    리뷰)이다.
*   **산문으로 남는 것:** NotebookEdit 은 잡지 않는다(기존). 이미 설치된
    프로젝트는 harness.env 에 키 한 줄을 손으로 넣는다(install 은 harness.env 가
    없을 때만 만들고, sync 는 이 키를 더하지 않는다). 지식 저장소 폴더는 슬롯에
    적지 않는다. 슬롯 저장소의 PR URL · 완료 주장을 변경 설명 · 완료 감사의
    입력에 넣는 것은 SKILL.md 의 산문 계약이고 기계 검증이 없다.

### 잡는 쪽 — Bash 스윕

Edit · Write · MultiEdit 은 아래 꼴도 잡는다. 못 잡는 것은 Bash 로 쓴 경우다.

*   **못 잡는 꼴:**
    *   쌍이 아닌 형제 저장소를 가리키는 상대경로 — cwd 가 clone A 일 때
        `../B/x.go` · `../_workspace_B/02_plan.md`, cwd 가 `_workspace_A` 일 때
        `../B/…`(쌍 = 저장소 T 와 옆 `_workspace_T`).
    *   cwd 가 슬롯 루트일 때의 상대경로(`T/src/x.go`).
    *   저장소만 가리키는 명령에서 무시 폴더(`.git` · `node_modules` · `.venv` ·
        `__pycache__`) 아래의 작업 공간.
    *   작업 공간 안 더 깊은 `_workspace*` — 작업 공간 뿌리는 한 단계만
        훑는다(`find -maxdepth 1`). 명령이 그 폴더를 직접 가리키면 잡는다.
    *   링크 뒤의 슬롯 작업 공간(`R/wl → 슬롯/_workspace_T`)에 쓴 설계물 — 작업
        공간 뿌리를 문자열 조상 이름으로 찾는다. 파일 심링크
        토큰(`R/x.go → T/src/x.go`)도 못 잡는다(`187398c` 부터 같다).
    *   목록을 읽을 수 없는 작업 공간(find 오류) — 무기록 · 무알림.
    *   슬롯 이름이 `_workspace*` 일 때 `cat > <슬롯>/00_design.md`.
    *   세션 루트가 슬롯 저장소 T 자신일 때 `../_workspace_T/` 에 쓴 설계물 —
        무알림.
    *   홈 토큰으로 읽지 않는 꼴: 중괄호 확장 `{~/a,~/b}` 안의 경로, 폴더 이름에
        `:` 가 든 저장소(`~/slot/T:x/…` — 토큰이 `:` 에서 끊긴다. 절대경로
        토큰도 `187398c` 부터 같다).
    *   변수 · 스크립트 안의 경로, 공백이 든 경로, mtime 을 보존하는 쓰기, 창
        없는 Bash · 취소 · 백그라운드(기존 — ADR-0024), 세션 루트 `_workspace/`
        를 무시하는 프로젝트의 Bash 설계물(기존).
    *   서브에이전트의 cwd 는 미확인이다.
*   **과하게 잡는 꼴**(게이트가 설 뿐 막지는 않는다):
    *   cwd 가 트랙 clone 이면 `git pull` · `rebase` · `switch` · `stash pop` ·
        `git clone` · 압축 해제로 바뀐 추적 파일 전부에 게이트가 선다. Bash 마다
        미커밋 삭제를 다시 판정한다.
    *   `..` 를 지나는 토큰(`~/S/_workspace_U/../T/…`)이 다른 트랙의 작업 공간과
        그 쌍을 뿌리로 삼는다 — 슬롯 밖으로는 새지 않는다.
    *   `..` 와 없는 폴더가 섞인 편집
        경로(`<슬롯>/T/gone/../../../outside/X/a.go`)가 슬롯 밖 파일을 슬롯
        저장소 의무로 잡을 수 있다 — 편집이 성공한 뒤면 폴더가 보통 있어 드물다.
    *   슬롯 자신이 git 최상위이고 다른 clone 이 그 안에 중첩되면 슬롯 전체가
        스윕 뿌리가 된다.
    *   `=` 뒤의 `~` 는 왼쪽이 식별자가 아니어도 단어 머리로 읽는다 — 그 이름의
        사용자가 실제로 있을 때만 "일부만 훑었다"고 알리고, 사용자 조회가
        실패하면 있다고 보고 알린다.
*   **상한:** 명령문 토큰 뿌리는 3개까지다. 넘거나 홈 토큰을 펼치지 못하면
    일부만 훑었다고 알린다.

### 시간 · 비용

*   **키를 켜면 시간 예산(20 s)과 뿌리 수집 절단이 키가 없을 때부터 훑던 모든
    뿌리에 걸린다** — 세션 루트 · 같은 저장소의 다른 체크아웃 · 명령문 절대경로
    저장소(하네스 정본 clone 포함). `187398c` 에는 예산이 없다. 부하가 큰
    기기에서 Bash 하나가 세션 루트 파일 수백 개를 바꾸면 20 s 에서 끊고 알린다 —
    나머지에는 게이트가 서지 않는다. 뿌리 수집 단계에서 끊기면 바꾼 파일이
    하나여도 기록 0 이다(알림은 나간다).
*   **예산이 못 끊는 구간:** 뿌리마다 find 순회 하나와 `git status` 1회, 홈 토큰
    추출과 사용자 조회(python3 `getpwnam` — `~단어` 수에 이차 비용, 조회 지연).
    환경에서 물려받은 `SECONDS` 는 곧바로 절단된다(알림).
*   **비용:** 링크를 거친 명령문 토큰은 토큰마다 git 을 조회한다(1000개 약
    7.5–8.9 s, 3000개면 시간 절단 알림). 홈 토큰(`~/…`) 수집에는 캐시가
    없다(같은 저장소 1000개 약 14 s, 2000개면 시간 절단 알림). 둘 다 알림이
    나가므로 조용한 누락은 아니다.
*   **과알림:** 설계물이 약 194개를 넘으면 먼저 도는 작업 공간 판정이 판정
    상한(200)을 먹어 절단 알림이 과하게 남는다(막는 쪽).
*   **Stop:** 미충족 5000개 판정 약 1.1–1.9 s, 기록 10000줄에서 막음 1.63 s ·
    해제 1.18 s(macOS bash 3.2 실측 — 미충족 나열은 항목 수에 선형).
*   **발행 게이트 ②** 는 리뷰 자리 수 × 자리의 파일 수만큼 본다.
*   **기록 파일은 덧붙이기만 해서 커진다** — 판정당 2줄, 약 288 B(추정 — 경로
    길이에 비례). 1000 판정이면 약 288 KB 다.

### 푸는 쪽 — 리뷰 자리와 수명

*   **슬롯 항목은 현재 기록 자리로만 풀린다.** 세션 루트 리뷰는 인정하지 않고,
    자리마다 리뷰가 필요하다. 자리는 폴더라서 같은 자리에 다른 세션이 둔
    리뷰로도 풀린다. 다시 고치지 않은 값은 그 편집이 일어난 옛 소속 자리로 푼다.
*   **순서 제약:** 모든 자리의 리뷰를 마지막 편집 뒤에 써야 한다 — 리뷰는
    듀얼리뷰 플래그보다 새로워야 하고, 편집 하나가 플래그를 새로 쓴다.
*   **해제 실패가 넓어진다:** 잔류 Bash 창(ADR-0024 후속 이력)과 창 없이 도는
    미커밋 삭제 재판정이 플래그를 다시 쓰면, 그 전의 모든 자리 리뷰가 낡는다.
*   **결속의 남는 틈:** 한 판정에서 갱신 표시와 현재 기록이 **둘 다** 일시
    장애로 실패하고 Stop 전에 회복되면 옛 줄이 현재로 남는다 — 옛 소속 자리
    리뷰로 풀릴 수 있다. 그 저장 때 기록 실패 알림이 나가므로 조용하지는 않다.
    지속 장애 가운데 권한 · 파일 종류는 record-unusable 로 막힌다. 공간 부족은
    쓰기 가능 검사(`-w`)를 통과하므로 일시 장애와 같은 틈이다 — 세션 폴더와 리뷰
    자리가 같은 파일시스템이면 그동안 리뷰 산출물도 쓸 수 없어 해제는 공간이
    회복된 뒤에만 가능하고, 그 저장 때 기록 실패 알림이 나간다. 공간 부족 주입은
    CI 에 이식할 수 없어 기계 시험이 없다.
*   **기록 실패의 방향**(회복 가능 알림의 "그 전까지 그 값은 턴 종료에서
    막히거나 옛 소속 자리 리뷰로 풀릴 수 있다"가 가리키는 경우들):
    *   ① 갱신 표시만 실패하고 ③ 이 성공하면 끝줄이 현재 기록이라
        정상이다(알림은 나간다).
    *   ③ 만 실패하면(② 플래그 갱신이 실패해도) 끝줄이 갱신 표시라 Stop 이
        막는다. 회복 가능한 원인(일시 쓰기 실패 · 권한 · 파일 종류 · git 판독)을
        고친 뒤 다시 저장하면 missing-record 가 해소되고, 그 뒤 기록 자리
        리뷰로 풀린다. 영구 실패 — 갱신 표시는 1023바이트
        안이지만 현재 기록 줄(값과 자리 경로들)만 넘는 값 — 은 다시 저장해도
        같은 제한으로 ③ 이 실패해 풀리지 않는다(아래 "기록할 수 없는 값").
    *   ①·③ 이 둘 다 일시 실패하면 위 "결속의 남는 틈"이다.
*   **병렬 판정과 소속 변경:** 같은 값의 두 판정이 병렬로 돌고 그 사이 소속(가장
    안쪽 git 최상위 · 슬롯 범위)이 바뀌면, 늦게 끝난 판정의 현재 기록이 옛 소속
    자리일 수 있다 — kty 수용 2026-10-12(설계 게이트 종결 결정).
*   **슬롯이 꺼진 동안의 갱신:** 슬롯이 꺼진 동안(harness.env 판독 불가 · 값
    불량)의 판정이 같은 값의 플래그를 갱신하면(예: `T/_workspace/00_design.md`
    는 기존 설계 글롭이 잡는다) 기록 줄이 늘지 않아 옛 줄이 현재로 남는다.
*   **가운데 줄 찢김:** 끝이 잘린 줄은 모르는 꼴로 막지만, 앞선 덧붙이기가 개행
    없이 잘린 채 다음 줄이 이어 붙으면 그 줄은 앞 줄에 흡수된다 — 그 값의 끝줄이
    옛 자리 줄이면 옛 소속 자리 리뷰로 풀릴 수 있다(성립 조건이 길다).
*   **기록할 수 없는 값:** 기록 줄이 1023바이트를 넘는 값과 경로에 US(0x1F)가 든
    값은 다시 저장해도 · 이름이나 위치를 바꿔도 이번 막음이 풀리지 않는다 — 옛
    값이 플래그에 남는다. 슬롯 안 `.claude/` 앵커 파일의 저장소를 git 이 읽지
    못하면(소유권 · 권한 · 손상) git 이 고쳐질 때까지 같다. 출구는 사용자 판단 ·
    사용자 전용 탈출구 · 같은 지점 3회 차단 뒤 통과뿐이다. git 판독 실패는
    사용자가 git 을 고친 뒤 다시 저장하면 — 기록할 수 없는 값이 아니면 — 기록돼
    missing-record 가 해소되고, 그 뒤 기록 자리 리뷰로 풀린다(시험 v19 · v21 ·
    v24). 키 줄을 지우거나 값을 비우는 것도 사용자 판단이다 — 그러면 세션 루트
    리뷰로 풀린다(harness.env 를 정상으로 읽을 수 있을 때만 — 다른 키가 손상됐으면
    그것부터 고친다).
    슬롯이 꺼진 동안 막힌 1023바이트 값은 Stop 이 먼저 꺼진 까닭(값 검증 실패 ·
    harness.env 판독 불가)대로 "고친 뒤 다시 저장하라"고 안내하고, 그대로 한
    뒤의 Stop 이 영구라는 안내를 낸다.
*   **세션 루트 경로에 개행 · US** 가 있으면 판정하지 않고 막는다(root-unusable
    — rc 4 의 뜻이 기록 파일 사용 불가에서 넓어졌다). 키에 값이 있으면(값이
    틀려도) 기록 파일이 없어도 막고, harness.env 를 믿고 읽을 수 없으면 기록
    파일이 있을 때 막는다. 듀얼리뷰 플래그가 있는 턴마다 막힌다.
*   **평가할 수 없을 때 기록 파일이 있으면 막는다:** 모듈이 유실되거나 평가가
    실패하면 세션 루트 항목만 남은 묶음도 막힌다(출구 — 모듈 유실 · 오류는 sync,
    판독기 awk · 임시 파일의 환경 장애는 사용자 판단). 평가가 신호로 끝나면(rc
    128 이상) Stop 은 원인을 가리지 못한다 — 모듈 탓이면 sync 로 풀리고 자원
    한도 같은 환경 탓이면 다시 설치로 풀리지 않아, 사용자 판단을 안내한다(시험
    v25). 근사 대조를 걷어낸 대가다(대안 F).
*   **이중 실패**(기록 파일 없음 + 평가 실패)는 기존 루프다 — 판정자도 기록하지
    못한 경우다.
*   **키를 세션 중에 켜면** 그 전에 플래그에 오른 슬롯 안 절대경로 항목은 기록이
    없어 missing-record 로 막힌다 — 그 파일을 다시 저장하면 기록된다. 기록할 수
    없는 값(위)은 다시 저장해도 기록되지 않는다.
*   **키 줄을 지우거나 값을 비우면**(키 없음 — 사용자 판단) 기록된 슬롯 의무도
    세션 루트 리뷰로 풀린다(기존 동작 보존). 단 harness.env 를 정상으로 읽을 수
    있을 때만이다 — 다른 키가 손상됐으면(UNTRUSTED) 기록 파일이 있는 한 기록으로
    판정하므로 그것부터 고친다(시험 v28). 값만 틀리게 바꾸는 것("슬롯 꺼짐")은 이
    출구가 아니다 — 기록이 있으면 기록으로 판정한다.
*   **풀릴 때는 dir-unknown 사유가 나오지 않는다:** 값 검증 실패나 harness.env
    판독 불가 동안 기록 없는 슬롯 절대 항목이 세션 루트 리뷰로 풀리면 "슬롯
    폴더를 알 수 없어" 사유는 출력되지 않는다 — 사유는 막음 안내에만 실린다.
    저장 쪽 슬롯 알림이 먼저 나가는 이중 장애 경로다.
*   **막힘 예산은 자리별 진전을 세지 않는다:** 차단 지문에 기다리는 자리의
    진전이 들어가지 않아, 자리가 여럿일 때 하나씩 저장하며 Stop 을 되풀이하면
    같은 지점 차단으로 센다 — 한 번에 모두 저장해야 한다.

### 알림 · 설정

*   **키 문법이 좁다** — 폴더 하나, 절대경로나 `~/`, `:` · `/` · `~사용자` ·
    `$HOME` 은 쓸 수 없고 있는 폴더여야 한다.
*   **알림은 세션마다 같은 사유당 한 번이다.** 사유가 정상화된 뒤 다시 생기면
    다시 알린다. 세션 번호가 없는 옛 입력은 표식을 공유한다.
*   **harness.env 를 믿고 읽을 수 없으면 키를 쓰지 않는 설치본도 알린다**(하위
    호환 범위의 kty 결정 — 아래 "의도된 차이" 1).
*   **저장 때 알림이 모델 문맥에 들어가는지는 미확인이다**(PostToolUse 의
    `systemMessage`). 그래서 Stop 막음 안내가 출구를 다시 말한다. 배포 실측에서
    확인한다.
*   **발행 게이트 ② 가 기록을 읽지 못한 채 세션 루트 리뷰로 통과하면** 알림만
    내고 통과시킨다(슬롯 모드에서만).
*   **SIGPIPE:** 훅 stdout 을 읽는 쪽이 먼저 닫히면 완료 게이트 훅이 신호로
    죽어(rc 141) `|| exit 0` 에 닿지 못한다. `187398c` 부터 키와 무관하게 같은
    성질이고, 알림은 출력이 성공했을 때만 표식을 쓰므로 다음 호출이 다시 낸다.
    고치면 키 부재 장애 경로의 종료 코드가 바뀌어(하위 호환) 기록만 했다.

### 보안 LOW — 적대 방어 범위 밖

*   기록 덧붙이기는 `.review-dirs` · 세션 폴더 심링크를 따라간다(기존
    `record_flag` 와 같은 부류 — 하네스가 만들지 않는 링크다).
*   `sibling_repo_of` 는 `_workspace_..` · `_workspace_.` 같은 이름의 `..` · `.`
    을 정규화하지 않는다 — 문자열 비교로 "슬롯 안"이 될 수 있다(드물다).
*   harness.env 를 지운 뒤 다시 쓰는 비원자 저장 도중의 훅 호출 하나는 키가 없는
    것으로 판정할 수 있다(검사-사용 경합 — 코드 판독 근거, 원자적 rename
    저장에는 틈이 없다).
*   가운데 줄 찢김 · `..` 토큰 과탐 · `..` 와 없는 폴더가 섞인 경로는 위 각 절에
    적었다.

### 시험의 판별력

*   시험 v18(슬롯 자리 목록을 `LC_ALL=C` 로 다룬다)은 GNU grep 에서만 적색이
    난다 — UTF-8 로케일의 GNU grep 은 잘못된 UTF-8 이 든 줄을 이진으로 보지만,
    macOS 의 BSD grep 은 그렇지 않아 결함이 나타나지 않는다. CI(ubuntu)가
    지킨다.

## 키가 없을 때의 의도된 차이

정상 harness.env 에 키가 없거나 값이 비면 stdout · stderr · rc · 상태 파일이
`187398c`(이 슬롯 이전의 main)와 바이트 같다. 앞서 슬롯 알림 표식
`.extra-gate-notice` 가 남아 있던 세션은 그 표식이 지워진다는 점만 다르다.
의도된 차이는 셋이고 모두 PR #52(잡는 쪽)에서 생겼다. 풀기 쪽(Stop · 발행 게이트
· 이 문서)은 1번을 한 자리 넓혔을 뿐 새 차이를 더하지 않았다 — 정상 harness.env
의 키 부재 · 빈 값 바이트 대조는 122/122 같다.

1.  harness.env 자리가 이상하거나(폴더 · 끊긴 링크 · 일반 파일 아래), 읽을 수
    없거나, **다른 키** 내용이 손상됐으면(안 닫힌 따옴표 · 히어독) 키가 없어도
    슬롯 알림이 나간다. 편집 검증 훅은 그 자리에서 경고하고, 완료 게이트 훅은
    같은 사유가 이어지는 동안 세션마다 한 번 알린다. 풀기 쪽이 넓힌 자리: 이
    상태에서 앞서 키가 켜져 기록 파일이 생긴 세션이면 Stop · 발행 게이트도
    기록으로 판정한다(결정 표의 UNTRUSTED 행).
2.  stdout 이 닫혔을 때 `187398c` 는 stderr 에 `write error` 를 내지만 새 훅은
    아무것도 내지 않는다.
3.  히어독 임시 파일을 만들지 못하면 옛 코드는 순회를 0회 돌고(무음 fail-open)
    새 코드는 끝까지 훑는다.

## 되돌리기

*   이 결정은 PR 둘로 들어갔다 — PR #52(잡기: 키 판독 · 판정 · 기록)와 그 위의
    풀기 PR(Stop · 발행 게이트 · 이 문서). 풀기 PR 을 먼저 되돌린다 — 잡기 PR 이

    기록을 읽지 않고, 슬롯 항목도 세션 루트 리뷰로 풀린다.
