# ADR-0024: 완료 게이트는 편집 도구가 아니라 파일 변경을 본다

**Date**: 2026-09-05
**Status**: accepted
**Deciders**: 김태윤(지시 — "둘 다 막아"), Claude(설계·구현)

---

## Context

완료 게이트 플래그를 세우는 `mark-needs-audit.sh` 는 `PostToolUse` 의
`Edit|Write|MultiEdit` 에만 걸려 있었고, 페이로드의 `tool_input.file_path` 하나로 판정했다.

**그래서 Bash 로 쓴 파일은 게이트를 통째로 지나쳤다.** `cat > 파일` · `sed -i` ·
`python3 스크립트` · `cp` — 전부 무게이트다.

실물로 드러났다: 2026-09-04~05 세션이 하네스 정본(`template/.claude/*`)을 통째로 고쳤는데
파일을 전부 Bash 로 썼고, 그 결과 **감사·변경설명·지식반영·듀얼리뷰 플래그가 하나도 서지
않았다.** 우회 의도는 없었다 — 그 세션은 "Bash 를 우선 쓰라"는 모드로 돌고 있었다.
의도가 없어도 결과는 같다: 게이트가 있다고 믿는 쪽이 없는 것보다 나쁘다.

같은 세션에서 확인한 것 하나 더: **프로젝트 자신의 `.claude/` 편집에 플래그가 안 서는 것은
구멍이 아니라 설계다.** `classify()` 가 `.claude/*` 제외를 앵커 판정보다 먼저 두는 것은,
정본 저장소가 자기 자신에 설치해 둔 소비 사본이 발화하지 않게 하려는 의도적 순서다.
이 ADR 은 그 규칙을 건드리지 않는다.

## Decision

**게이트의 입력을 "어떤 도구를 썼나"에서 "무엇이 바뀌었나"로 옮긴다.**

1.  **`mark-bash-window.sh`(PreToolUse/Bash)** 가 명령 직전에 `.claude/.bash-window` 를
    빈 파일로 찍는다. 내용은 없고 **mtime 만** 의미가 있다.
2.  **`mark-needs-audit.sh`(PostToolUse/Bash 추가 등록)** 가 그 표식보다 새로 바뀐 파일을
    찾아 판정한다. `file_path` 가 있으면 기존 경로 그대로, 없고 `command` 가 있으면 스윕이다.
3.  **명령을 파싱하지 않는다.** 무엇을 썼는지 명령줄에서 알아내려는 시도는 히어독·리다이렉트·
    스크립트 호출마다 새는 구멍을 만든다. `find -newer` 로 **결과**를 본다 — 명령이 어떻게
    썼든 mtime 은 거짓말하지 않는다.
4.  **판정은 자기 재호출로 위임한다.** 스윕이 찾은 파일마다 이 스크립트를 `file_path`
    페이로드로 다시 부른다. `classify()` 의 사본을 만들지 않으려는 것이다 — 사본을 두는
    순간 두 판정이 어긋나는 날이 온다(이 저장소가 반복해서 배운 것).
5.  **탐색 범위는 프로젝트 + 명령문에 등장한 절대경로의 git 루트(최대 3개).** 하네스 정본은
    **다른 클론**에서 고쳐지는 일이 잦다(2026-08-04 실사고). 이건 명령 해석이 아니라 탐색
    범위 힌트라, 틀려도 프로젝트 스캔은 그대로 돈다.
6.  **git 이 무시하는 파일은 제외한다.** 빌드 산출물은 소스가 아니다. `git check-ignore
    --stdin` 으로 한 번에 걸러내고, 그 위에 `find` prune 목록(`.git`·`node_modules`·
    `vendor`·`dist`·`build`·`target`·`.next`·`__pycache__`·`_workspace`·`worktrees`)을 둔다.

## Consequences

**좋아지는 것**

- 파일을 무엇으로 썼든 게이트가 선다. 이 ADR 을 만든 세션 자신이 반례였다.
- 명령 파싱이 없으므로 새 쓰기 방법(새 CLI·새 스크립트 언어)이 나와도 구멍이 안 생긴다.

**대가**

- **Bash 호출마다 `find` 가 돈다.** prune 으로 묶었고 대상 저장소가 작아 실측 부담은
  작지만, 거대한 저장소에서는 무시할 수 없다. PostToolUse timeout 을 30초로 뒀다.
- **위양성이 남는다.** 명령이 도는 동안 사람이 편집기로 고친 파일은 그 명령이 쓴 것으로
  잡힌다. PreToolUse 로 창을 명령 실행 구간에 맞춰 줄였지만 0 은 아니다.
- **표식이 없으면 스윕은 잠든다.** `mark-bash-window.sh` 를 등록하지 않은 설치본에서는
  기존(Edit/Write) 동작만 남는다. 조용히 오작동하는 대신 **조용히 예전 동작으로 축퇴**하는
  쪽을 골랐다 — 새 훅이 없는데 스윕이 엉뚱한 창으로 도는 것보다 낫다.
- 훅이 하나 늘었다(9 → 10). `settings.json` 등록 2건(PreToolUse/Bash 맨 앞, PostToolUse/Bash).

**듀얼 리뷰 r1 이후 남긴 위음성 2건 (미조치 공시)**

둘 다 막으려면 이 설계가 명시적으로 거부한 수단이 필요해서 두었다.

- **명령문의 절대경로에 공백이 있으면 외부 저장소 스캔이 그 경로를 놓친다.** 토큰 추출이
  공백에서 잘리기 때문이다. 정확히 하려면 명령을 파싱해야 하는데, 그것이 이 ADR 이
  피하려던 바로 그 방법이다. **프로젝트 스캔은 영향받지 않는다.**
- **스윕 상한(200)이 `classify` 제외 파일까지 센다.** 앞 200개가 문서·`.claude/*` 라면
  201번째 소스는 검사조차 안 받는다. 무엇이 게이트 대상인지는 재호출된 자식만 아는데,
  부모가 미리 세려면 `classify` 사본을 부모에 둬야 한다 — 사본 금지가 이 설계의 전제다.
  대신 **상한에 걸리면 `systemMessage` 로 알린다**(조용한 누락은 없다).

**병렬 호출 처리(창 여러 개)**

표식이 하나면 병렬 Bash 가 서로를 지워 먼저 쓴 파일이 통째로 사라진다(듀얼 리뷰 r1
CRITICAL). 그래서 호출마다 창 파일을 만들고 PostToolUse 는 **가장 오래된 창**을 소비한다.
짝이 정확히 맞지는 않지만 항상 더 **넓은** 창을 쓰므로 누락이 없다 — 게이트에서 과탐은
싸고 누락은 비싸다. 짝이 안 맞아 남은 창은 60분 뒤 정리한다.

## Alternatives considered

- **PreToolUse 에서 쓰기 명령을 차단하고 Edit/Write 로 유도** — 무엇이 쓰기인지 판정하려면
  명령을 파싱해야 하고, 새는 차단기는 마찰과 헛된 안심을 동시에 만든다.
- **`git status --porcelain` 으로 감지** — `.claude/` 가 `.git/info/exclude` 로 빠진
  프로젝트에서는 하네스 편집이 안 보인다. 실제 pokeclip-mono 가 그 상태다.
- **PostToolUse 에서 이전 스윕 시각을 창으로 재활용(PreToolUse 훅 없이)** — 창이
  [이전 명령 끝 ~ 지금] 으로 벌어져, 그 사이 사람이 고친 파일까지 잡힌다. 훅 하나를 더
  등록하는 값이 그 위양성보다 싸다.

## 후속 이력

- **2026-10-08 — 실패한 Bash 도 창을 소비한다**: Claude Code 가 도구 실패로 처리해
  `PostToolUseFailure` 를 발화한 Bash(예: `false` — 2026-10-08 실측)에는 `PostToolUse` 가
  발화하지 않는다([훅 문서]). 종료 코드가 0 이 아닌 Bash 가 전부 이 경로로 가는지는
  단정하지 않는다 — 실측한 것은 `false` 이고, 어떤 Bash 결과가 실패로 분류되는지는
  [도구 문서]의 Bash 절이 정한다(r1 리뷰 인용). 스윕이 `PostToolUse/Bash` 에만 걸려 있어
  실패로 처리된 호출의 창이 소비되지 않고 남았다(`false` 한 번에 1개, 실세션 약 110개).
  그 옛 창이 "가장 오래된 창"이 되어 리뷰·설명이 끝난 파일이 Bash 마다 다시 플래그에
  올랐고, `record_flag` 의 `touch` 로 플래그 mtime 이 계속 새로워져 리뷰 산출물에 의한
  자동 해제(ADR-0017)가 영영 안 됐다. `settings.json` 에 `PostToolUseFailure/Bash` →
  `mark-needs-audit.sh` 를 등록해 등록이 3건이 됐다. 훅 본문은 `tool_response`·이벤트
  이름을 읽지 않으므로 고치지 않았다(같은 판정). 회귀 방어는
  `tests/bash-write-sweep.test.sh` 12–15(배선은 type · 명령까지 글자 그대로 대조, 실패
  입력은 `session_id` · `cwd` · `is_interrupt` 를 실은 모양, 15 는 듀얼리뷰 플래그가 리뷰
  산출물보다 새로워지지 않음).

  **남는 한계:**

    - **남은 창은 60분 정리만이 아니라 다음 Post 가 소비한다.** 스윕은 호출의 짝을 찾지
      않고 가장 오래된 창을 쓴다. 어느 Post 도 발화하지 않은 호출(권한 거부·PreToolUse
      차단으로 시작조차 안 한 호출)의 창은 그 뒤 Bash 의 Post 가 하나씩 소비하고, 그
      스윕은 옛 창 기준이라 같은 오탐(끝난 파일 재플래그 · 플래그 `touch`)을 낸다. 남은
      창이 k개면 이후 Bash k번에 걸쳐 이어진다.
    - **60분 정리는 타이머가 아니다.** 다음 `PreToolUse/Bash`(`mark-bash-window.sh`)가 돌
      때 `find -mmin +60 -delete` 로 지운다. 그 전에 Post 가 먼저 소비하면 위 오탐이 난다.
    - **이미 쌓인 창은 이 수정이 즉시 지우지 않는다.** 실세션의 약 110개는 위 두 경로로만
      줄어든다.
    - **백그라운드 Bash** 는 반환할 때 Post 가 창을 소비하므로, 그 뒤에도 도는 명령의
      쓰기는 스윕이 못 잡는다(기존 한계).
    - **후속 후보(미구현 · kty 회부):** `tool_use_id` 로 창을 짝짓는다 — Pre 가 그 id 로
      창을 만들고 Post 가 자기 창만 소비하면, 시작 못 한 호출의 창이 다른 호출을
      오염시키는 문제와 동시 Post 의 중복 소비가 함께 줄어든다.
