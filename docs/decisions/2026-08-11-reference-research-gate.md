# ADR-0015: 레퍼런스 조사도 표명이 계약이다 — 회수 게이트를 머리 표명 게이트로 일반화한다

**Date**: 2026-08-11
**Status**: accepted
**Deciders**: 김태윤(요구 원문·확정 5건), Claude(설계·듀얼 검수 3라운드)

---

## Context

**요구 원문 요지 (kty, 2026-08-10):** *"계획 세울 때 레퍼런스 조사를 강제했으면 한다. 내가
그냥 조사해오라고 했으면 너는 절대 Netflix 조사 안 했을 거다 — 라이브 스트리밍 서비스가
아니니까. 조사가 필요하다고 판단되는 지시사항에 대해서만, 기계적 게이트로 무조건 실시하게
할 수 있나?"*

계기는 실측이다: pokeclip 미디어 사이드카(DVR·S3) 설계에서 선행 기술 조사가 0회였고,
답은 정확히 **인접 도메인**에 있었다 — "라이브가 아닌 Netflix"를 제외했으면 못 찾았을
Netflix Live Origin(2025-12 TechBlog — S3→KV 전환·payload chunking·segment-template
manifest). 이 관측이 새 의무 신설의 전제("실제로 새는 것을 본 뒤")를 채운다.

**판정 프레임** — ADR-0012 ⑤·⑥과 ADR-0013 의 구분 그대로: "조사가 필요한 지시인가"의
**판정은 기계 불가**다(키워드·카테고리 목록은 임의 목록 부류). 기계가 막을 수 있는 것은
판정의 **무표명 통과**뿐이다. 표명 의무는 새 의무의 신설이라 관측 우선 규칙의 적용
대상인데 그 관측이 위에 있고, 신설된 의무의 형식 검증은 그 순간부터 산문 승격 부류다
(산문 절차 불이행은 이 저장소가 반복 실측한 부류 — ADR-0013 Alt E 와 같은 논거).

용어 4분법: **판정**(조사 필요 여부 — 기계 불가) · **실행**(collector→evaluator — 산문
계약) · **표명**(산출물 둘째 줄 — **여기만 기계**) · **심사**(사유 타당성·조사 품질 —
검수 층 산문 계약).

설계 전문·검수 3라운드 기록은 `_workspace/00_design-reference-gate.md`(v3)·
`24/27/30_design_r*_integrated.md`(근거 raw 는 상위 층 지식 저장소의 이 프로젝트 specs 에 보존).

## Decision

### ① 표명 — 설계·계획 산출물 둘째 줄, 닫힌 문법 세 변형

```
1줄: 사전 결정 회수: <경로>              또는  없음(<사유>)          (ADR-0013 — 불변)
2줄: 레퍼런스 조사: 조사함(<대상·출처>) | 불요(<사유>) | 실패(<시도 — 사유>)
3줄~: - 걸리는 선행 결정: …              (회수 블록 — ADR-0013 ④-⑴에서 위치만 이동)
```

- **불요에도 사유 강제**가 핵심이다 — `불요` 단독·빈 괄호는 불량. 조용한 스킵 불가화
- `실패` 는 "필요하다고 판단했으나 실행이 실패했다"를 있는 그대로 적는 칸(사용자 확정 ⑤)
  — `불요` 에 접으면 단어 뜻과 실제가 어긋나 표명이 거짓이 된다
- 문법: `레퍼런스 조사:<SP*><변형><SP*>(<내용>)<SP*>` — 변형은 세 단어 **정확 일치**
  (꼬리 문자 불량), SP 는 ASCII 스페이스·탭뿐, 내용은 `LC_ALL=C tr -d '[:space:]'` 후
  비어있지 않음(내부 괄호 허용 — 마지막 `)` 가 닫는 괄호), 닫는 괄호 뒤엔 SP 만
- **둘째 줄 고정**인 이유: 첫 줄은 선점됐고, 회수 블록은 가변 길이라 "블록 다음" 앵커가
  성립하지 않으며, "N줄 이내" 스캔은 임의 숫자 부류다. 결정적 앵커는 이것뿐이다

### ② 기계 — 새 게이트가 아니라 3.4 의 일반화

기존 회수 표명 게이트(3.4)가 파일마다 검사하는 항목을 첫 줄 하나에서 **머리 두 줄**로
늘린다. 플래그(`.needs-retrieval`)·`work_pending`·공유 지문의 존재 비트·자동 해제·재평가·
지문 재계산·`decision_armed` 비편입·개행 방어 — 상태기계 전부 재사용이다. 신설안
(`stop:reference`)은 직전 세션 검수가 실측 결함을 잡았던 결합면 8종을 정보 이득 없이 다시
걷는 설계라 기각했다(ADR-0012 ⑥ "범위→단순" — 검사할 줄이 는 것은 게이트의 범위이지 새
판정이 아니다).

- **예산 키 항목이 `<경로>#검사번호`(#1 첫 줄/#2 둘째 줄)로 확장된다** — 경로만 넣으면 두
  줄 다 불량인 파일의 첫 줄만 고친 진전이 키를 못 바꿔, 4회째 예산 소진이 플래그 5종을
  전삭제한다(설계 검수 [cx]가 잡은 경로). 사유 문자열은 넣지 않는다 — 같은 검사의 사유
  변화는 진전이 아니다
- 둘째 줄 읽기는 read 의 rc 를 분기로 소비한다(`if read / elif [ -n ] / else 누락`) —
  무개행 마지막 줄에서 read 가 값을 담고도 rc=1 을 내기 때문이다. 한 줄 관용구
  (`read || [ -n ]`)는 단발 read 에서 no-op 임을 검수가 적발했다([cc] r2 HIGH)
- 내용 검사는 세 변형 **공통 단일 경로**다 — 변형별 복제는 한 변형만 검사가 빠지는 부류를
  만든다(`실패()` — [cx] r2 HIGH)
- 차단 헤드라인·플래그 판독 불가 메시지가 "머리 표명" 공통 문구로 바뀐다 — 옛 문구를
  유지하면 둘째 줄 단독 불량에서 게이트가 거짓 진단("회수 표명이 없습니다")을 낸다

### ③ 실행 배선 — 전부 산문 계약 (SKILL Phase 2)

오케스트레이터가 Phase 2 진입 시 조사 필요를 판단한다(기준: 설계 결정이 조직 밖 공개
선례·경쟁 구현·실패 사례에 따라 달라질 수 있는가 — 전 작업 기본 조사가 아니다. 비용:
에이전트 2 dispatch). 필요 시 `research-collector`(인접 도메인 지시 상수 포함) →
`research-evaluator` → 채택분을 architect·planner 프롬프트에 주입. 실행 주체가
오케스트레이터인 이유: 참조 에이전트는 Read·Grep·Glob 뿐이라 조사를 못 하고, 표명은
작성자 손에 있어야 검수가 작성자의 판단을 심사할 수 있다.

경계 조건(검수가 잡은 비종결 경로들): evaluator 재수집은 1회만 · 채택 0건은
`조사함(<범위> — 채택 0건)` 으로 표명(그것도 조사의 결과다) · 실행 실패는 기존 에러
규칙("결과 없이 진행하되 누락 명시")을 따르되 **표명이 그 명시 자리**(`실패(…)`) ·
작성자의 "조사 필요" 반환 재dispatch 1회 · 검수의 "조사 재시도 필요" 보류는 작성자가
아니라 **조사 단계로** 되돌리고 조사 사이클 총 상한 2회, 소진 후엔 사용자 "결정 필요"로
승격 · research 에이전트 미설치면 오케스트레이터 대체 수행 + 명시.

### ④ 심사 — 레퍼런스 검증 3항목 (회수 검증 3항목의 짝)

plan-reviewer 점검 항목(6-2)과 설계·계획 pass 의 codex 프롬프트 계약에: ① 표명이 형식대로
있는가 ② **불요 사유가 타당한가 — 인접 도메인을 좁게 잘라 불요로 넘기지 않았는가**("라이브가
아니니 Netflix 는 안 본다" 부류 명시 심사). 실패면 사유·재시도 필요성 ③ 조사함이면 본문에
실제 반영·인용됐고 출처가 재검증 가능한가. 전부 산문 계약이다.

### ⑤ 조사 산출물 — 이름을 규정하지 않는다

collector/evaluator 의 자체 계약(`_workspace/research/01_collected.md`·`02_evaluated.md`)이
정본이다. `_workspace/` 는 mark-needs-audit 의 skip 분류라 게이트·재귀·명명 정합 문제가
원천적으로 없고, 하네스 소유 이름 신설은 관측된 필요 없는 새 규약이다(관측 우선).

## Alternatives Considered

### A. "조사 필요" 판정을 기계로 (키워드·카테고리 목록)
- **Why not**: 임의 목록 부류(ADR-0012 ⑥). 결정 게이트의 어휘 목록에서 거부한 것과 같은
  추측 위의 추측. kty 확정 요지가 이미 기각했다

### B. 표명을 산문으로만 (게이트 없음)
- **Why not**: 산문 절차 불이행은 반복 실측 부류(2026-08-02·08-03) + "기계적 게이트" 명시 요구

### C. `stop:reference` + `.needs-reference` 신설
- **Pros**: 두 표명을 개별로 켜고 끌 수 있다
- **Cons**: 상태기계 결합면 8종 재주행 — 각각이 실측 결함이 났던 자리다
- **Why not**: 같은 지뢰밭을 정보 이득 없이 두 번 걷는다. 개별 끄기 수요는 관측 없음

### D. 조사함에 URL 정규식 의무
- **Why not**: 유효 출처 형태(사내 문서·서적·수집물 경로)를 임의 목록으로 좁히고 내용
  검사에 침범. 재검증 가능성 심사는 검수 몫

### E. evaluator 판정 인용을 기계로 의무화
- **Why not**: 실행 자체가 산문 계약인데 인용만 기계로 강제하면 "지어낸 인용"을 유도한다

### F. 조사 산출물 이름 `_workspace/02_research.md` 규정
- **Why not**: mark-needs-audit 대상 여부·듀얼리뷰 관계·명명 정합을 전부 새로 정해야 하고
  이득은 "이름이 예측 가능"뿐

## Consequences

### Positive
- "조사가 필요했는가"라는 질문이 설계·계획마다 **강제로 답해진다** — 답이 불요여도 사유가
  남아 검수가 심사할 대상이 생긴다. 조용한 스킵(요구의 계기)이 불가능해진다
- 인접 도메인 계약이 조사 지시문 상수가 된다 — "라이브가 아니니 Netflix 제외" 부류가
  심사 항목으로 명시된다
- 상태기계 재사용으로 기계 면적 증가가 최소다(검사 항목 1 + 예산 키 태그)

### Negative — 이 정책이 못 막는 것
- **조사했다는 사실 자체는 기계가 못 본다.** `조사함(지어낸 출처)` 는 형식 통과 — 검수
  (산문·확률적)와 감사자 몫
- **출처가 아예 없어도 통과한다** — `조사함(Netflix)` 처럼 대상만 적은 표명. 출처 요구는
  검수 항목 ③
- **불요·실패 사유의 타당성은 기계가 못 본다** — `불요(시간 없음)` 도 형식 통과
- **조사 실행은 기계가 강제하지 않는다** — dispatch·품질·재수집 상한·실패 접기 전부 산문
- **예산 소진은 두 표명을 함께 면제한다** — 진전 없는 3회 차단 후 벽돌 방지 통과가 플래그를
  전삭제한다(기존 게이트 공통 트레이드오프. #1/#2 태그가 "부분 진전인데 소진" 경로는 닫았다)
- **`00_design*`·`01_plan*` 이름 밖 산출물은 면제** — mark-needs-audit 이름 계약 이월
- **`stop:retrieval` 하나로 두 표명이 함께 꺼진다** — 개별 끄기 없음. 그리고 게이트 ID
  **이름이 계약보다 좁다**(회수만 가리키는 이름이 두 표명을 검사) — 저장소 밖 사용처(셸
  설정·CI)에 박힌 ID 라 유지했고 괴리를 공시한다
- **결정 게이트(3.2) 위양성이 구조적으로 는다** — 불요·실패 사유 서술문("~라서 안
  했습니다")이 표지 어휘에 걸릴 수 있다. 완화: 사유를 보고에 인용할 때 백틱/따옴표로
  감싼다(구조적 제외 장치의 정상 사용). 걸리면 질문 한 번이면 풀린다
- **r04(0바이트 파일)는 두 검사의 격리 예외** — 빈 파일 첫 줄 분기의 단독 변이는 두지
  않는다(공시된 측정 공백. 빈 줄 분기 자체는 r50+m35 가 격리 측정한다)
- 세 단어·반각 괄호 밖 유의어(`불필요`·전각 괄호)는 불량 판정 — 메시지가 형식 전문을
  안내한다. 유니코드 공백만 든 괄호는 바이트 판정상 통과한다(공시)
- 삭제 우회·도구 밖 생성·서브에이전트 직접 저장 미실측 — 기존 3.4 공시 이월
- clarifier·ADR 트리거에는 레퍼런스 표명 의무가 없다 — 좁게 시작, 새는 실측이 나오면
  확장 재검토(관측 우선)
- 배포 시점 어긋남: 훅은 세션 시작 스냅샷 — 구 게이트+새 SKILL 은 무해(1줄 검사는 머리
  계약의 부분집합), 새 훅+구 SKILL 산출물은 차단 후 메시지가 안내(ADR-0013 과 같은 롤아웃)
