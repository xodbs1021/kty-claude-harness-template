# ADR-0014: 배포 경로에도 측정·정합 가드를 세운다 — 변이 락은 무조건 거부, dirty 는 옵트인

**Date**: 2026-08-10
**Status**: accepted
**Deciders**: 김태윤(C안 확정), Claude(설계·구현)

> 번호 참고: ADR-0013(지식 회수 정책)은 PR #19 에 있다. 이 ADR 이 먼저 머지되면 번호가
> 잠시 건너뛰지만, 번호는 발행 순서지 머지 순서가 아니다.

## Context

실사고(2026-08-10): 변이 하네스가 도는 중에 정본 트리를 워크트리로 복사해, 표지 판정이 빠진 훅이 세션에 들어갔다. 배포 전에 해시를 비교했는데도 못 봤다 — **둘 다 변이본이었으니까.** 변이 하네스 자신은 dirty 검사와 락을 갖고 있었지만, 배포 경로(`install.sh`·`sync.sh`)에는 아무 검사가 없었다.

단순한 "HEAD 와 다르면 거부"는 정상 개발 흐름을 깬다 — 템플릿을 고치고 프로젝트에 설치해 시험하는 것이 일상이다. 이 갈림이 앞 세션에서 발견돼 사용자 질문으로 넘어왔고, C안이 확정됐다.

## Decision

**`scripts/deploy-guard.sh` 의 `deploy_guard()` 를 `install.sh`·`sync.sh` 가 배포 전에 지난다.**

1. **변이 락(`$GIT_DIR/mutate-*.lock`)이 있으면 무조건 거부 — 옵트인 없음.** 측정 중 배포는 언제나 틀리다. 죽은 프로세스의 잔류 락은 사람이 `rmdir` 로 걷어낸다(메시지가 안내한다). 락 이름 규약은 변이 하네스 3종(`mutate-decision-gate`·`mutate-harness-env`·`mutate-retrieval-gate`)이 이미 쓰던 것이다 — 새 규약을 만들지 않았다.
2. **정본 트리가 dirty 면 거부하되 `--allow-dirty` 로 옵트인.** 거부 메시지가 옵트인을 안내한다 — 안내가 없으면 막힌 사람이 우회를 발명한다. `sync.sh` 는 받은 옵트인을 내부 `install.sh` 호출에 그대로 넘긴다(안 넘기면 같은 옵트인을 두 번 강요당한다).
3. **sync 의 가드는 pull 보다 앞이다.** 변이 측정 중에 pull 로 트리를 바꾸면 변이 하네스의 복원 앵커까지 깨진다.
4. **판정 불가의 방향:** 정본이 git 저장소가 아니면(락·dirty 가 정의되지 않는 형태) 검사를 생략하되 소리를 낸다. git 저장소인데 `status` 가 실패하면 "모름"이므로 fail-closed 로 거부한다 — 이때도 `--allow-dirty` 가 탈출구다. 가드 파일 자체가 없으면(부분 복사본) 경고를 내고 진행한다 — 조용한 생략 금지.
5. **통과 경로의 안내 출력은 최선 노력(`|| true`)이다.** stderr 가 닫힌 환경에서 안내 echo 하나가 `set -e` 아래 정상 설치를 죽였다(구현 중 기존 테스트 c08 이 실측으로 잡음). "계약은 종료 코드지 출력이 아니다" — 신호 핸들러와 같은 부류다.

## Alternatives Considered

### A. 락 거부 + dirty 는 경고만
- **Pros**: 개발 흐름을 전혀 안 건드린다
- **Why not**: 경고는 무시되면 사고가 그대로다 — 이 저장소에서 산문·경고가 생략된 실사고가 반복됐다

### B. dirty 거부 + 옵트인만 (락 검사 없음)
- **Pros**: 더 단순하다
- **Why not**: 실제 사고의 직접 원인이 락(측정 중)이었다. 측정 중 트리는 커밋 상태와 무관하게 순간순간 바뀌므로 dirty 검사만으로는 창이 남는다

### C. 둘 다 (채택 — 사용자 확정)

### D. "HEAD 와 다르면 거부" (옵트인 없음)
- **Why not**: 템플릿 수정 → 시험 설치라는 일상 흐름을 깬다. 강제 장치가 개발을 인질로 잡으면 사람이 장치를 끈다

## Consequences

### Positive
- 측정 중 배포(실사고의 부류)가 기계로 막힌다 — 배포 경로가 변이 하네스와 같은 안전 수준이 된다
- dirty 배포가 **의식적 행위**가 된다 — 무엇이 나갔는지 git 이 말할 수 없는 상태는 명시 옵트인 뒤에만

### Negative — 이 가드가 못 막는 것
- **락은 협조적 신호다.** 변이 하네스가 락을 만들지 않으면(규약 위반) 못 본다. 세 하네스가 관례를 지키는 것이 전제다
- **TOCTOU 창**: 가드 통과 직후 변이 측정이 시작되면 못 본다 — 가드는 시작 시점 스냅숏이다
- `--allow-dirty` 는 상태를 안 가린다 — 옵트인한 dirty 배포가 잘못된 트리를 내보내는 것 자체는 사용자 책임으로 남는다
- git 이 아예 없는 환경(PATH 에 git 부재)은 rev-parse 실패 → "git 저장소가 아님" 경로로 떨어져 검사가 생략된다(공시)

## 기계적 장치

`tests/install-hook-swap.test.sh` 에 케이스 4건(c10~c13): 락 거부+대상 무변경 · dirty 거부+옵트인 안내 문구 · 옵트인 시 dirty 상태가 실제로 배포됨(시험 설치의 목적) · 락은 옵트인으로도 안 뚫림. 거부 케이스는 rc 만이 아니라 **대상 디렉터리가 안 만들어졌는지**까지 잰다 — 가드가 늦게 서면 rc 는 같아도 반쯤 배포된다. 가드 케이스는 실저장소가 아니라 **독립 픽스처 정본**(자기 git 저장소)으로 잰다 — 실저장소에 락·dirty 를 만들면 테스트가 개발 트리를 오염시킨다.
