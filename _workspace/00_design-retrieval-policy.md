# 지식 회수 정책 — 설계서 (2026-08-10)

## 0. 입력

ADR-0010 이 못박은 공백 4개(트리거·선택·표명·claude-mem 분업)를 닫는다. 사용자 확정 4건(AskUserQuestion, 2026-08-10):

| 물은 것 | 확정 |
|---|---|
| ② 선택을 누가 하나 | **중간안** — 맥락 전달 + 회수 프로토콜 계약화, 선택은 진입점을 읽는 에이전트 판단 |
| ① 트리거 확장 범위 | **clarifier + 결정 시점 + developer 주소만** |
| ③ 표명 형식 검사 기계화 | **Stop 게이트로 기계화** (내용 검증은 층 위반이라 불가 — 형식만) |
| 2순위 배포 가드 | **C안** (변이 락 무조건 거부 + dirty 거부/`--allow-dirty` 옵트인) — 별도 작업 |

공시: 위 응답 4건은 모두 즉각 반환됐고 전부 추천안과 일치한다 — 인계 문서 9절 5항("즉답으로 돌아온 답은 의심해라")에 해당하므로, 이 확정은 PR 리뷰에서 사용자가 뒤집을 수 있는 것으로 취급한다. 설계 근거는 응답과 독립적으로 아래에 전부 적는다.

## 1. 판정 프레임 — 무엇을 기계로, 무엇을 단순하게

ADR-0012 ⑤·⑥절의 기준을 그대로 쓴다:

> 게이트를 기계로 두는 이유는 판단이 못 미더워서다. 범위를 정교하게 깎는 것은 게이트를 강하게 만들지 않는다 — 버그는 고치고, 정교함은 참는다.

이 설계의 각 결정에 같은 물음을 적용했다 — 지금 없는 것이 **판단의 실패**인가(→ 기계), **범위의 문제**인가(→ 단순하게). 그리고 임의의 숫자·목록을 지어내야 하는 안은 전부 의심하고 기각했다(어휘 목록에 대한 사용자 지적과 같은 부류).

서술은 **주소 / 트리거 / 선택**을 갈라서 한다. ADR-0010 이 셋을 섞어 쓴 것이 혼선의 한 원인이었다:

- **주소** — 지식이 어디 있는지. 프로필 9절 경로 하나. **변경 없음** (ADR-0009 확정 유지)
- **트리거** — 언제 읽는지. **이번에 넓힌다** (2절)
- **선택** — 무엇을 읽는지. **프로토콜만 계약화하고 판단은 위임** (3절)

## 2. 결정 ① 트리거 — 어디서 회수를 발동하나

각 후보에 "여기서 회수하면 무엇이 달라지나"와 "토큰 값을 하나"를 적는다.

| 트리거 | 달라지는 것 | 토큰 값을 하나 | 판정 |
|---|---|---|---|
| architect·planner 착수 전 (현행) | 설계·계획이 선행 결정 위에서 시작 | 이미 지불 중 | **유지** |
| **clarifier — 질문 전** | 과거 결정으로 답이 되는 질문이 사용자에게 안 간다. 질문 소음↓ = 결정 게이트의 위양성 비용 논리와 같은 축("질문이 소음이 되면 진짜 질문도 무시된다") | 진입점+파일 몇 개 읽기 < 사용자 질문 1회의 비용 | **채택** |
| **새 결정을 내리는 순간 (ADR 작성 전)** | 같은 결정의 재결정·선행 결정과 모순되는 결정이 작성 전에 걸린다. ADR-0009 가 진단한 병("같은 결정을 매번 다시 내리고 그 재결정이 또 저장된다")을 정확히 겨눈다 | ADR 은 드물다(트리거 자체가 "대안을 기각하고 방향 확정") — 비용 미미, 값 최대 | **채택** |
| **developer — 주소만** | "이 부분 전에 어떻게 정했더라"가 나올 때 갈 곳이 생긴다. 의무 읽기는 아니다 | 주입은 경로 한 줄 — 0에 가깝다 | **채택 (주소만)** |
| developer 착수 전 의무 회수 | — | 계획서가 이미 회수된 지식을 담고 온다. 같은 지식을 층마다 다시 읽으면 토큰만 쓰고 판단은 안 바뀐다 | **기각** (ADR-0009 Alt C 사유 유지) |
| 검수자(reviewer) 회수 | — | 검수 기준은 프로필 §4 불변식이 그 자리다 — 선행 결정 중 검수에 걸릴 것은 §4 로 증류되는 것이 정본 경로 | **기각** |

**developer 의무화를 하지 않는 이유를 판정 프레임으로 다시:** "구현 중 회수가 더 잦다"는 관찰은 맞지만, 그 순간이 언제인지는 기계가 못 본다(에이전트의 판단이다). 판단을 기계로 대체할 수 없으면 주소를 주고 습관을 관찰한다 — 실제로 안 읽어서 새는 것을 본 뒤에만 승격한다(이 저장소의 게이트 증설 규칙 그대로).

## 3. 결정 ② 선택 — 결정이 100건이면 무엇을 읽나

**중간안: 하네스는 "무엇을 찾는지"를 주고, 선택은 진입점을 읽는 에이전트의 판단에 맡긴다. 대신 회수의 절차를 계약으로 명문화한다.**

### 회수 프로토콜 (dispatch 계약에 들어갈 문장)

```
1. 프로필 9절의 진입점을 읽는다.
2. 진입점이 목차·라우팅이면, 이번 작업(디스패치 프롬프트의 작업 요약)과 관련된
   항목만 따라가 읽는다. 전부 읽지 않는다.
3. 그 너머의 전문 탐색(grep 등)은 진입점 라우팅으로 부족할 때의 최후 수단이다.
4. 무엇을 읽었고 무엇이 걸리는지를 회수 블록(4절 형식)으로 낸다.
```

### 층 경계 논증 — 이것이 ADR-0006 을 위반하지 않는 이유

- 프로토콜이 가정하는 것은 "진입점은 진입점이다"뿐이다 — 목차 파일 하나가 다른 파일을 가리킨다는 것은 **공개 포맷**이지 특정 저장소의 사유화된 배치가 아니다. **공개 포맷 의존은 층 위반이 아니다. 사유화된 배치 의존이 위반이다** (이월된 결정). 볼트의 4종 세트·`decisions/` 구조 같은 구체 이름은 프로토콜에 없다.
- "무엇을 찾는지"는 하네스가 이미 가진 정보다(디스패치 프롬프트의 작업 요약) — 새 결합 없음.
- 선택의 품질은 여전히 진입점 너머 라우팅에 달렸다. **하네스가 보장하는 것**: 회수가 시도된다는 것, 절차가 계약이라는 것, 표명 형식이 검증된다는 것. **보장하지 않는 것**: 올바른 파일이 선택된다는 것, 읽은 내용이 옳게 반영된다는 것.
- 전제: 상위 층 CI 가 링크 무결성·인덱스 완전성·canon 포인터를 보장한다(이월된 결정). 이 전제가 깨진 저장소에서는 회수 품질이 그만큼 내려가고, 하네스는 그것을 감지하지 못한다 — 공시.

### 기각한 대안

- **(a) 상위 층 회수 인터페이스("질의 → 경로 목록") 신설** — 상위 층에 새 규약과 유지보수 의무가 생기고, 하네스가 그 규약의 형식을 알아야 하므로 계약 표면이 넓어진다. 결정적으로, 기계 질의가 서려면 frontmatter 스키마가 서야 하는데 **실측이 반대다**(타입별 스키마 미정의, `status` 59%·`related-projects` 27% 누락 — 대부분 "해당 없음"이라 필터를 못 짠다). 관측 없이 규약을 지어내는 설계 = 임의 목록 부류. 새는 것을 실제로 본 뒤에 재검토.
- **(b) 현재 유지(공시만)** — "알아서 읽어라"는 세션마다 다른 절차를 낳는다. 절차의 부재는 판단 문제가 아니라 **계약 부재**라 비용 없이 닫을 수 있는데 안 닫을 이유가 없다.
- **(c) `harness.env` 에 결정 경로 슬롯(구 C안)** — 기각 사유 이월: 볼트 `canon-path` 를 볼트 CI 가 이미 검증하므로 중복이고, 사용자가 패턴 목록을 유지보수하게 만들어 자동화 목적에 역행한다.

## 4. 결정 ③ 표명 — 강제로 올릴 수 있나

**내용의 기계 검증은 층 위반 없이는 불가능하다 — 못 푼다고 적는다** (ADR-0009 Alt D 사유 유지: "읽었는가"를 기계가 확인하려면 하네스가 그 경로의 내용 구조를 알아야 한다). 대신 세 단계로 올린다:

### 4-1. 표명을 두껍게 (형식 계약)

산출물 첫 줄은 현행 유지(기계 검증 대상):

```
사전 결정 회수: <읽은 경로>          또는          사전 결정 회수: 없음(<사유>)
```

이어서 **회수 블록**(첫 줄 직후, 산문 목록):

```
- 걸리는 선행 결정: <결정 제목 — 이번 작업에 어떻게 걸리는지 한 줄> (0건이면 "걸리는 선행 결정 없음")
```

읽은 파일이 진입점뿐이 아니면 첫 줄에 이어 적는다. 지어낸 회수는 경로 한 줄보다 목록이 더 큰 거짓말이 되고, 아래 4-2 의 검증 대상이 생긴다.

### 4-2. 내용 검증은 검수 층으로 (기존 기계 위에 얹는다)

plan-reviewer dispatch 계약에 추가: ① 회수 블록이 형식대로 있는가 ② 산출물이 "걸리는 선행 결정"과 모순되는가 ③ 걸린다고 적힌 결정이 설계·계획에 실제로 반영됐는가. plan-reviewer 는 이미 듀얼리뷰 게이트(훅)로 강제되는 자리다 — **새 기계 없이 기존 기계의 검사 항목을 늘리는 것**이라 산문 승격 규칙에 안 걸린다.

### 4-3. 형식 검증은 Stop 게이트로 (신규 기계 — `stop:retrieval`)

**판정 프레임 적용:** "오케스트레이터가 첫 줄 확인을 잊는다"는 판단 실패 부류다 — 산문 계약이 잊힌 실증(2026-08-03 sync 누락 사고)이 있고, SKILL.md 의 "첫 줄에 있는지 확인한다 — 없으면 되돌린다"는 정확히 그런 산문이다. `_workspace/00_design*.md`·`01_plan*.md` 는 **하네스 소유 산출물**이라 첫 줄 형식 검사는 층 위반이 아니다. 임의 숫자·목록 없음 — 형식은 이미 있는 계약이다.

```
mark-needs-audit(PostToolUse): 00_design*.md·01_plan*.md 저장 시
  → .needs-retrieval 플래그에 경로 기록 (기존 dualreview·knowledge 와 같은 자리)

verify-before-stop(Stop, 게이트 3.4 — 결정 게이트 뒤·듀얼리뷰 앞):
  플래그의 각 경로에 대해 첫 줄이 "사전 결정 회수:" + 비어 있지 않은 내용인가
  → 전부 정상: 플래그 자동 해제 후 통과 (수동 rm 불요 — 준수가 곧 해제)
  → 하나라도 불량·빈 파일·읽기 실패: 차단 + 어느 파일이 왜인지 출력 (fail-closed)
  → 플래그에 적힌 파일이 사라짐: 그 항목은 건너뛴다 (공시된 한계 — 아래)
```

- **자동 해제**가 이 게이트의 형태다. 결정 게이트가 "실제로 물으면 풀린다"이듯 이것은 "형식을 지키면 풀린다" — 지울 플래그를 에이전트 손에 주지 않는다.
- **fail-closed 인 이유:** 이 게이트의 위양성 비용은 메시지 한 번이다(사용자에게 가는 질문이 아니다) — 집안 표준대로 위양성 쪽으로 기운다. 결정 게이트만 예외였던 이유(질문 소음)가 여기 없다.
- **순서(3.4)의 근거:** 표명 없는 산출물로 리뷰(3.5)에 노력을 쓰기 전에 잡는 편이 싸다. ADR-0012 ④와 같은 비용 논리이고, 정확성 문제가 아니므로 옮기는 변이로 잰다.
- **파일 소실을 건너뛰는 이유:** 차단하면 산출물을 아카이브한 턴이 벽돌이 된다(파일을 지웠으니 고칠 대상이 없다). 산출물 실존 요구는 듀얼리뷰 게이트가 이미 들고 있다 — 이 게이트는 형식만 맡는다. 삭제로 우회하면 듀얼리뷰 게이트가 잡는다.

## 5. 결정 ④ — `claude-mem` 과의 분업

| | 지식 진입점 (프로필 9절) | claude-mem |
|---|---|---|
| 성격 | **큐레이션된 결정 기록** (정본) | **압축된 세션 히스토리** (전량·손실) |
| 질문 | "전에 무엇을 **정했나**, 왜" | "전에 무엇을 **했나**, 비슷한 걸 풀었나" |
| 쓰는 곳 | architect·planner 착수 전 · clarifier 질문 전 · ADR 작성 전 | Phase 0 착수 시 1회 검색 (현행 유지) |

**충돌 규칙: 큐레이션이 이긴다.** claude-mem 은 압축본이라 추론의 결이 손실된다(SKILL.md ADR 절이 이미 공시). 둘이 어긋나면 진입점 쪽 기록을 따르고, 어긋남 자체를 사용자에게 보고한다(큐레이션이 낡았을 수도 있다 — 판정은 사용자 몫).

## 7. 기계적 장치 — 테스트·변이 계획

케이스(형제 스위트 규약 준수 — rc 단독 판정 금지, 통과 케이스는 후속 게이트가 실제로 말했는지 요구):

4. 빈 파일 → 차단
5. 접두어만 있고 내용 없음(`사전 결정 회수:` 뒤 공백뿐) → 차단

9. `ECC_DISABLED_HOOKS=stop:retrieval` → 통과

## 8. 공시된 한계 (ADR Consequences 로 갈 것)

- **읽었다는 것은 여전히 기계가 못 본다.** 형식 게이트는 "표명이 형식대로 있다"까지만. 내용은 plan-reviewer(LLM)가 본다 — 기계가 아니다.
- **선택 품질 보장 없음** — 진입점 너머 라우팅과 상위 층 CI 전제에 달렸다.
- **회수 블록을 지어내는 에이전트는 기계로 못 잡는다** — 잡는 것은 검수 층이고, 그것도 확률적이다.
- **파일 소실 항목 건너뜀** — 삭제로 형식 게이트를 우회할 수 있다(듀얼리뷰 게이트가 산출물 실존을 별도로 요구하므로 조합 우회는 비싸다).
- **결정 문서를 `docs/decisions/` 밖에 두면 지식 게이트가 안 선다**(mark-needs-audit 공시의 이월) — 하네스는 자기가 규정한 경로만 안다. 다른 위치 인식은 상위 층 구현 지식이라 층 위반. 닫지 않고 공시 유지.
- **developer 의 실제 회수 습관은 관측 대상** — 주소만 준 것이 부족하면(안 읽어서 새는 실측이 나오면) 그때 승격.

## 9. ADR 번호 판단

**ADR-0013 신설 + ADR-0010 은 superseded.** 재작성(proposed→accepted)하지 않는 이유: ADR-0010 의 Decision 은 "정책을 정하지 않는다 — 공백을 못박는다"이고 그 결정은 그 자체로 실행됐다(공백 4개가 이 설계의 입력이 됐다). 내용을 갈아끼우면 "공백이 명시적으로 선언됐던" 이력이 사라진다 — ADR-0006 의 proposed→accepted 는 결정 내용이 동일한 채 이행만 완료된 경우라 성격이 다르다.
