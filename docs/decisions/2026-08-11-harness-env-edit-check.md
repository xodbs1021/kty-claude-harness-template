# ADR-0016: harness.env 편집 실수는 그 자리에서 알린다 — 판독기 반환 계약을 3분화하고 편집 검증 훅을 단다

**Date**: 2026-08-11
**Status**: accepted
**Deciders**: 김태윤("1번만 하고 2번은 기각" 확정 + "지금 만들어줘"), Claude(구현·듀얼 검수)

---

## Context

`harness.env` 는 실행되지 않고 좁은 문법으로 판독된다(ADR 계보: 실행하면 `exit 0` 한 줄로
게이트 4종이 흔적 없이 사라진 실측). 그 대가가 공시돼 있었다: **문법을 조금만 틀리면 값이
조용히 미설정 취급되고 해당 검사가 생략된다.** 원인(편집 실수)과 발각(턴 종료 게이트 메시지
구석) 사이가 멀고, 못 보면 "타입체크가 돌고 있다고 믿는데 몇 주째 안 도는" 상태가 된다 —
이 저장소가 제일 무겁게 치는 **조용한 실패** 부류다.

인계된 함정: 판독기(`harness_env_value`)는 "키 없음"(정상 — 안 쓰는 키)과 "문법 밖"(실수)을
**둘 다 rc=1** 로 냈다. 그대로 훅을 달면 키를 안 쓰는 프로젝트의 모든 편집에 경고가 떠
소음이 된다. 그리고 훅이 문법을 다시 해석하면 규칙이 두 벌이 된다(규칙의 사본 금지).

같은 후보 목록에 있던 반복 차단 카운터는 **기각**됐다(kty 확정 — 사례 1건·결정 게이트
중복·위양성 위험 > 방어 가치. 시끄러운 실패라 손실은 토큰뿐).

## Decision

### ① 판독기 반환 계약을 3분화한다 (구분의 정본은 판독기 하나)

```
rc=0 : 판독됨 (빈 문자열일 수 있다 — "리터럴로 비웠다")
rc=1 : 값을 믿을 수 없다 — 읽기 실패·선언 2개 이상·지원 문법 밖·닫히지 않은 따옴표/히어독.
       고칠 수 있는 실수다
rc=3 : 부재 — 파일 없음·최상위 선언 0개. 안 쓰는 키의 정상 상태다
```

- 3 을 쓰는 이유는 `decision_scan` 과 같다 — awk 의 비정상 종료(rc=2 등)가 정상 부재로
  위장되지 않게, 정상 경로에 흔한 코드를 주지 않는다(모르는 rc 는 전부 rc=1 로 접는다 —
  fail-closed)
- **기존 호출부는 전부 "rc!=0" 처리라 동작 불변** — 지식 게이트는 1·3 모두 켜짐(부재=기본
  보존, 못 믿음=fail-closed), 타입체크는 둘 다 생략. 구분을 소비하는 곳(신설 훅·생략 사유
  문구)만 갈라 읽는다
- 둘째 인자로 판독할 파일을 지정할 수 있다 — 훅이 "방금 편집된 그 파일"을 읽어야 한다

### ② 편집 검증 훅 `check-harness-env.sh` (PostToolUse)

`.claude/harness/harness.env` 편집 직후, 알려진 키(`HARNESS_TYPECHECK_CMD`·
`HARNESS_KNOWLEDGE_GATE`)를 **실제 판독기로** 읽어 rc=1 인 키만 systemMessage 로 경고한다
— "이 키는 미설정으로 취급되고 해당 검사가 조용히 생략됩니다". rc=0·rc=3 은 침묵.
차단하지 않는다(PostToolUse — 항상 exit 0). 탈출구 `post:edit:harness-env`.

- 경로 앵커는 `.claude/harness/harness.env` 까지 요구 — 동명 무관 파일 오탐 방지
- 개행 경로·상대경로 처리는 mark-needs-audit 관용구 그대로

## Alternatives Considered

### A. 훅이 문법 규칙을 자체 해석해 사유를 알려준다
- **Why not**: 규칙의 사본 — 두 규칙이 어긋나는 날이 온다(이 저장소가 판독기 회귀 6종에서
  데인 부류). 판정은 판독기 하나뿐이어야 한다

### B. rc 구분 없이 "지금 이렇게 읽힌다" 표만 보여준다
- **Why not**: 부재와 실수를 못 가르면 표가 매 편집마다 뜨거나("미설정 또는 문법 밖") 소음.
  경고가 소음이 되면 진짜 경고도 무시된다 — 결정 게이트에서 확립된 논거

### C. Stop 게이트로 차단(경고가 아니라 강제)
- **Why not**: 설정 파일 편집은 사람이 하는 일이고, 문법 실수의 피해는 검사 생략(다른
  게이트가 사유를 적는다)이지 오염이 아니다. 편집 즉시 정보만 주면 충분 — 과설계 금지

## Consequences

### Positive
- 조용한 검사 생략의 발각 시점이 "턴 종료(또는 영원히)"에서 **편집 즉시**로 당겨진다
- 부재/실수 구분이 판독기 계약이 되어, 타입체크 생략 사유도 정확해진다("미설정" vs
  "값을 믿을 수 없음 — 고칠 수 있는 실수")

### Negative — 못 막는 것 (공시)
- **알려진 키 목록 밖은 못 잡는다** — 오타 키(`HARNESS_TYPECHEK_CMD`)는 선언 파싱 없이는
  탐지 불가고, 그 파싱이 곧 규칙의 사본이다. 키 로스터는 훅 안 한 곳이 유일 지점
- 경고는 정보일 뿐 강제가 아니다 — 무시하면 기존과 같은 상태로 돌아간다
- 도구 밖 편집(`bash echo >> harness.env`)은 PostToolUse 앵커 밖 — 기존 게이트 공통 한계
- root 환경에서는 읽기 실패 케이스가 재현 불가(테스트가 사유 명시 후 건너뜀)
