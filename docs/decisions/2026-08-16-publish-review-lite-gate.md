# ADR-0022: 발행 게이트는 축소판으로 — 영수증(ADR-0018/PR #25) 기각, "최근 리뷰 실존" 검사로 대체

- 날짜: 2026-08-16
- 상태: 채택 (kty 확정 — "니가 추천하는 방향으로 추진")
- 관련: ADR-0018(외부 발행 영수증 게이트 — **이 결정으로 기각**, 번호는 영구 결번) · ADR-0011(자기규율 게이트=방지턱) · ADR-0016(판독 실패를 조용한 생략으로 만들지 않는다)
- 번호 각주: 0021은 미머지 covenant 브랜치(PR #28)에 예약돼 있어 건너뛴다. 다음 번호는 "디렉터리 내 최대 번호+1"이 아니라 **예약분 포함 최대+1**로 매길 것.

## Context

2026-08-14 실사고: 스파이크 판정 4건이 듀얼 리뷰 없이 Jira 코멘트·위키로 발행됐고, 사후 리뷰에서 4건 전부 변경요청이 났다(그중 "S3 쓰기 비크리티컬"은 RPO 크리티컬로 뒤집혔고, 계약 결함 1건이 새로 발견됐다). 대응으로 리뷰 영수증 게이트(ADR-0018, PR #25 — 훅 339줄·digest 정규화·nonce·원자 소비·WAL, 총 +4,117줄)가 설계·구현·검수까지 끝났으나 **등재 0건으로 출하**된 채 처분 미결로 남아 있었다.

2026-08-16 kty 재검토 판정: **"문제의식은 옳았고 답의 크기가 틀렸다."**
- 선언된 위협은 "작정한 위조"가 아니라 "깜빡 누락"인데(훅 머리 자기 공시), 기계는 위조 대비급이었다 — 제0원칙 5(과설계 금지) 위반.
- 가치는 후불(도구별 payload 캡처를 또 지불해야 등재 가능), 비용은 선불(4,117줄이 즉시 유지 대상) — 지불 계획 없는 유휴 기계는 유령·드리프트 감사 부채가 된다(같은 날 하네스 전면 감사가 잡은 실물 부류).
- 검수 3라운드 내내 "한 글자 차이" fail-open이 재생산됐다 — 모든 MCP 호출 앞에 서는 코드로는 위험 폭이 크다.

## Decision

1. **PR #25 는 머지하지 않고 닫는다.** ADR-0018 은 기각으로 확정, 번호 0018 은 영구 결번(재사용 금지 — ADR-0019 머리의 결번 사유 각주가 이미 그 번호를 가리킨다).
2. **축소판 `guard-publish-review.sh` 를 신설한다** (~110줄):
   - 검사 ①: `.needs-dualreview` 미해소 상태의 발행 deny — 리뷰 앞지르기 금지.
   - 검사 ②: 최근 WINDOW분(기본 180, `harness.env HARNESS_PUBLISH_REVIEW_WINDOW_MIN`) 내 `_workspace/*codex*.md` 실존 없으면 deny — 08-14 유형(리뷰 자체가 없던 발행)을 직접 차단.
   - Artifact `action:"list"` 는 조회라 통과. 판정 불가는 deny(fail-closed) — 구체적으로 `_common.sh` 소싱 실패, 창 값 판독 불가(`harness_env_value` rc=1: 중복 선언·문법 밖·읽기 실패), date 실패가 전부 차단이다. 미래 mtime 산출물은 "최근"으로 치지 않고, 창 산술은 10진 강제("08" 8진수 크래시 방지). — 전부 codex r1 지적 반영.
3. **등록부 = settings.json matcher.** 별도 registry 파일을 두지 않는다. matcher 는 **전체 앵커**(`^(…)$`)로 쓴다 — Claude Code matcher 는 비앵커 검색이라 앵커 없인 `getArtifact`·`ArtifactSearch` 같은 조회 도구까지 잡는다(codex r1 실측). 매칭 대상은 내용 운반형 발행 도구만: Jira 코멘트(`addCommentToJiraIssue`)·Confluence 생성/수정/코멘트·GitHub 코멘트/리뷰/파일 발행(`add_issue_comment`·`add_reply_to_pull_request_comment`·`pull_request_review_write`·`add_comment_to_pending_review`·`create_or_update_file`·`push_files`)·`Artifact`.
   - **티켓 발부·수정·전이(createJiraIssue·editJiraIssue·transitionJiraIssue)와 이슈 생성(issue_write)·PR 생성은 의도적으로 제외** — kty 지시(2026-08-16): "티켓 발부 정도는 리뷰 안 거치고 해도 상관없다." 08-14 의 피해 실체도 티켓이 아니라 코멘트·위키에 실린 판정이었다.

## 검증하지 않는 것 (공시)

- 리뷰한 내용 ↔ 발행하는 내용의 **일치**(digest 계열) — 리뷰 A 직후의 무관한 발행 B 는 통과한다. 시간창은 휴리스틱이다.
- **위조** — 영수증 방식도 같은 손(발급자=피감시자) 문제로 못 막던 것. 진정성 검증은 completion-auditor 사후 감사 몫.
- 등재 밖 도구, 하네스 밖 디렉터리에서의 발행.

"없는 방어를 있다고 믿는 상태가 제일 나쁘다"(ADR-031, media 하드닝 기각의 kty 기준) — 그래서 한계를 훅 머리와 여기에 같은 문장으로 못박는다.

## Alternatives Considered

- **PR #25 그대로 머지(영수증 전면판):** 내용 일치·재발행 재승인까지 잡는 유일한 안. 그러나 등재 0=실효 0에 유지 4,117줄, 위협-기계 불일치. **기각.**
- **순수 산문 규율 유지(게이트 없음):** 08-14 에 이미 한 번 뚫렸고, G2(조사 산출물 명명 게이트)도 영수증을 믿고 철회돼 커버가 없다. **기각.**
- **시간창 없이 "codex 산출물 존재만" 검사:** 한 번이라도 리뷰한 프로젝트에선 영원히 통과 — 검사가 1회용으로 퇴화. **기각.**

## Consequences

- Positive: 08-14 유형(리뷰 없는 판정 발행)이 기계로 막힌다. 코드 ~110줄+테스트 13케이스로 유지 부담이 통제 범위. 등록부가 배선 층 하나라 "이름 틀려 조용히 무력화" 표면이 줄어든다.
- Negative: 내용 불일치 발행은 통과한다(공시된 한계). 시간창 휴리스틱의 위양성(리뷰 직후 무관 발행 통과)·위음성(느린 세션에서 정상 발행 차단 — 창 조정으로 완화)이 있다.
- PR #25 검수의 fail-open 함정 카탈로그 중 축소판 테스트가 실제로 고정한 것: 비인용 글로브(공백 경로 케이스)·판독 불가 창 값(중복 선언)·8진수 산술("08")·미래 mtime·스치는 통과(차단 사유 문구 검증). stdout 오염·FIFO 는 이 훅 구조상 해당 부위가 없어 케이스를 두지 않았다(판정에 쓰는 외부 명령 출력이 stat·date 뿐이고 각각 실패 시 차단). 테스트는 CI(check-rules.yml)에 등록했다.
