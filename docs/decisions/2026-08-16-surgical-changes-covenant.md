# ADR-0021: 변경 규약(Surgical Changes)은 rule:core 밖 별도 규약으로 둔다

**Date**: 2026-08-16
**Status**: accepted
**Deciders**: 김태윤(방향 제시·배치 재결정), Claude(설계·codex 듀얼 리뷰 3라운드)

---

## Context

Karpathy 의 LLM 코딩 실패 관찰을 정리한 공개 저장소(multica-ai/andrej-karpathy-skills)를
분석한 결과, 그 4원칙 중 셋(가정 표면화·단순함·검증 가능한 목표)은 이 하네스에 이미 더
강한 형태(기계 강제)로 존재했지만 **"변경 범위 최소화(Surgical Changes)" 축은 PR 층
(pr-reviewer 점검 1)에만 있고 Phase 2 계획 검증·Phase 3 코드 검수에는 없었다.**
결함은 늦게 잡을수록 비싸다는 이 하네스 자신의 원칙과 어긋나는 공백이다.

처음에는 rule:core 6번 항목으로 흡수했다. 그러나 검증 과정에서 범주 불일치가 드러났다:

- rule:core 1~5는 **산출물 구조**의 속성이다 — 코드만 열면 언제든 판정된다.
- 6번은 **변경 과정(diff)**의 속성이다 — 요청서를 옆에 놓고 diff를 봐야 판정된다.
- 그 증거로, diff가 없는 계획 단계(plan-reviewer)에서 6번을 판정하려면 "바뀐 모든 줄 →
  제안된 모듈·파일·단계" 치환 각주가 필요했다(codex HIGH 지적). 넣자마자 번역 각주가
  필요한 규칙은 층이 안 맞는다는 신호다.
- 게다가 계획 수준의 범위 통제는 plan-reviewer 점검 1("요청하지 않은 확장이 끼지
  않았는가")에 이미 자기 언어로 존재했다 — 치환 각주는 중복 번역이었다.

## Decision

1. **rule:core는 1~5(산출물 구조)만 유지한다.** 신규 항목 입장 조건을 명문화한다:
   "코드만 보고 한 줄로 판정 가능한 산출물 구조 항목만 받는다."
2. **principles.md에 '변경 규약' 절을 신설한다** — rule:core 밖, 같은 파일. 단일 정본이며
   사본을 두지 않는다(복제가 없으면 드리프트도 없다). 내용: 요청 역추적·요청 밖 '개선'
   금지·내 고아만 청소(기존 죽은 코드는 지적만).
3. **각 역은 자기 계약의 문구로 집행한다**: developer(준수) · ecc:code-reviewer 검수 계약
   ⑧(diff 판정, 규약 지목) · pr-reviewer 점검 1(PR 위생) · plan-reviewer 점검 1(계획 수준).
4. **설치본 층에도 검사기를 배포한다**: 소스 레벨(이 repo)에는 루트
   `scripts/check-rule-copies.sh` + CI(check-rules.yml)가 이미 있었으나 install.sh가
   배포하지 않아 **설치본 문서의 참조는 유령**이었다(pokeclip 실측 — 파일 부재).
   설치본용 경량 검사기 `template/.claude/scripts/check-rule-copies.sh`를 신설·배포하고
   (마커 무결성 검증 포함, 소스 스캐너의 미등록 검출을 피하려고 마커 문자열은 조립식),
   Stop 게이트 3.1b(rulecopy)가 매 턴 실행해 어긋난 턴을 기계로 막는다.
   **두 층의 관계: 소스는 CI가, 설치본은 Stop 게이트가 지킨다.**
5. **규약에 경계선을 명시한다**: 이 규약은 diff의 **위생**을 제한하지 작업의 **완결**을
   줄이는 근거가 아니다. 실사고 — 도입 직후 에이전트(Claude)가 이 규약을 작업 범위에
   오적용해, 만든 규칙의 강제 장치 연결·정본 반영을 "요청 밖"으로 분류하고 멈췄다.
   요청의 자연스러운 파급은 요청의 일부다.

## Consequences

- (+) 변경 범위 축이 Phase 3부터 걸린다 — PR 단계까지 가기 전에 요청 밖 변경이 잡힌다.
- (+) rule:core 의 판정 가능성이 유지된다 — 모든 항목이 같은 입력(코드)으로 판정된다.
- (+) "기계 대조 없는 복붙 규칙은 유령"이 게이트로 봉합됐다 — 사본 드리프트는 턴을 못 끝낸다.
- (−) 변경 규약은 사본 없이 주입(principles.md 동봉)에만 의존한다 — 주입 계약이 깨지면
  도달하지 않는다. 주입은 오케스트레이터 공통 계약 ②가 보장한다.
- (−) Stop 게이트가 1종 늘었다(rulecopy). 스크립트 부재 시 생략이라 기존 설치본은 무해하나,
  게이트가 실리려면 재설치(install.sh)가 필요하다.

## 실험 종결 판정 (2026-08-17, kty)

pokeclip 선적용 실험(PR #28)을 **부분 채택**으로 종결한다.

- **채택**: 변경 규약 산문 3항 + 완결 축소 금지 경계선 + 검수 계약 ⑧ + plan-reviewer 범위 분담 문구.
  근거: 실험 이틀째에 규약 렌즈가 실제 HIGH 를 잡았다 — 하네스 게이트 수정 커밋에 무관한
  `_workspace*` 80파일·7.5만 줄이 쓸려 들어간 것을 codex 가 "변경 전부가 처방으로 역추적되는가"
  로 적발(2026-08-17). LLM 의 근처 코드 '개선'·쓸어담기 성향은 상수라 재발 부류다.
- **기각**: rulecopy 기계장치 사슬 전부 — 에이전트 정의 내 rule:core 사본, check-rule-copies.sh,
  Stop 게이트 3.1b, install.sh scripts/ 배포. 근거 셋: ① 오케스트레이터가 dispatch 시
  principles.md **전문을 주입**하므로 사본은 이중 급식이다 ② 규약 자신의 설계 원리("정본은 한
  곳뿐 — 복제가 없으면 드리프트도 없다")와 모순된다 ③ 사본 하나를 지키려고 검사기→게이트→배포
  4단 유지보수 사슬이 생긴다. 사본을 없애면 사슬 전체가 무의미해진다.
- **파생**: 이 판정으로 사본 구조 자체(실험 이전부터 존재)도 폐지 — plan-reviewer 7번은 주입
  기준으로 재작성, principles 의 사본 강제 문단은 단일 정본 선언으로 교체.
- 후속: PR #28 은 닫고 브랜치는 실험 기록으로 보존. 산문만 실은 축소 PR 이 이 판정의 이행이다.
