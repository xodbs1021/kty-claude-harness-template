## 무엇

**레퍼런스 조사 게이트 (ADR-0015).** 설계·계획 산출물 **둘째 줄**에 레퍼런스 조사 표명을 의무화하고, 기존 회수 표명 게이트(3.4)를 **머리 표명 게이트**로 일반화해 두 줄을 한 기계로 검사한다.

```
1줄: 사전 결정 회수: <경로>              또는  없음(<사유>)          (기존 — ADR-0013)
2줄: 레퍼런스 조사: 조사함(<대상·출처>) | 불요(<사유>) | 실패(<시도 — 사유>)   (신설)
3줄~: - 걸리는 선행 결정: …              (회수 블록 — 위치만 셋째 줄로 이동)
```

## 왜

kty 요구 원문 요지: *"계획 세울 때 레퍼런스 조사를 강제했으면 한다. 내가 그냥 조사해오라고 했으면 너는 절대 Netflix 조사 안 했을 거다 — 라이브 스트리밍 서비스가 아니니까."* 계기 실측: pokeclip 사이드카 설계에서 선행 기술 조사 0회 — 답은 인접 도메인(Netflix Live Origin, 2025-12)에 있었다.

"조사가 필요한 지시인가"의 **판정은 기계 불가**(임의 목록 부류 — ADR-0012 ⑥). 기계가 막는 것은 판정의 **무표명 통과**다: **불요·실패에도 괄호 안 사유가 비면 불량** — 조용한 스킵 불가화가 핵심. 조사 실행(research-collector→research-evaluator)·불요 사유 심사(plan-reviewer·codex 레퍼런스 검증 3항목)는 산문 계약으로 공시.

## 어떻게 (핵심 결정 — 상세는 ADR-0015)

- **3.4 일반화, 새 게이트 아님** (사용자 확정): 플래그·work_pending·지문·예산·자동 해제 상태기계 전부 재사용. 신설안은 직전 세션 검수가 실측 결함을 잡은 결합면 8종의 재주행이라 기각
- **예산 키 항목 = `<경로>#검사번호`** — 두 줄 다 불량인 파일의 부분 수정(진전)이 소진 전삭제로 빠지는 경로를 닫음(설계 검수 [cx])
- 닫힌 문법: 세 변형 정확 일치 · SP=ASCII 스페이스/탭 · `LC_ALL=C` 내용 판정 · 마지막 `)` 가 닫는 괄호 · 내용 검사는 변형 공통 단일 경로
- 둘째 줄 read 는 rc 를 분기로 소비(무개행 마지막 줄 방어 — 한 줄 관용구는 단발 read 에서 no-op 임을 검수가 적발)
- ADR-0013 ④-⑴·④-⑶에 갱신 주석(역참조) — 낡은 위치·기계 계약 안내 방지

## 못 막는 것 (공시 — ADR-0015 Consequences 전문)

- `조사함(지어낸 출처)`·출처 없는 표명·`불요(시간 없음)` 는 형식 통과 — 내용 심사는 검수(산문·확률적)
- 조사 실행·재수집 상한·재시도 전이는 전부 산문 계약
- `stop:retrieval` 하나로 두 표명이 함께 꺼짐 + 게이트 ID 이름이 계약보다 좁음(저장소 밖 사용처 때문에 유지)
- 결정 게이트 위양성 증가(사유 서술문이 표지 어휘에 걸림 — 인용 감싸기 계약으로 완화)
- 예산 소진 시 두 표명 면제 · 이름 밖 산출물 면제 · 0바이트 파일 격리 예외(r04) · sort 폴백 미측정(ADR-0013 이월)
