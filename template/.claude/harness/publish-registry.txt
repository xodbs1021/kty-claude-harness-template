# publish-registry.txt — 외부 발행 게이트(ADR-0018)가 지키는 도구 목록.
#
# **지금 활성 행은 0개다. 즉 게이트는 배선돼 있지만 아무 도구도 막지 않는다.**
# 조용한 상태가 아니라 공시된 상태다 — docs/usage.md 5절과 ADR-0018 에 같은 사실이 적혀
# 있다. 행을 추가하는 순간부터 그 도구의 호출은 리뷰 영수증 없이는 통과하지 못한다.
#
# 왜 비어서 출하하나: 이 목록의 각 행은 **실측된 사실**이어야 한다(아래 등록 절차).
# 도구 이름 한 글자, tool_input 의 필드 이름 하나가 틀리면 게이트는 "미등재"로 접혀
# 조용히 사라지거나, 반대로 정상 발행을 영영 막는다. 추측으로 적은 행은 둘 중 하나다.
#
# ── 형식 (엄격하다. 어기면 판독기가 rc=1 로 떨어지고 게이트는 **전 도구를 deny** 한다) ──
#   탭으로 구분된 5칸, 정확히 5칸:
#     <tool_name>  <min_tier>  <waivable>  <artifact_field>  <body_field>
#
#   tool_name       도구의 **전체 이름**(예: mcp__foo__createIssue). [A-Za-z0-9_.-] 만.
#   min_tier        1 | 2 — 이 도구가 요구하는 최소 등급. 영수증 tier 가 이보다 낮으면 deny.
#                   상태를 바꾸는 폭이 크거나 되돌리기 어려운 발행은 2(= kty 승인 추가).
#   waivable        yes | no — 본문이 `[비판정]` 으로 **시작할 때** 영수증을 면제하는가.
#                   코멘트류만 yes 다. createIssue·editIssue·전이·Artifact 는 no.
#   artifact_field  tool_input 안에서 **발행 파일 경로**를 담은 점 경로, 없으면 `-`.
#                   지정하면 게이트가 그 파일을 재해시해 digest 에 섞는다.
#   body_field      tool_input 안에서 **본문**을 담은 점 경로, 없으면 `-`.
#                   waivable=yes 인데 `-` 면 형식 오류다(면제 판정을 할 수 없으므로).
#
#   빈 줄과 `#` 로 시작하는 줄은 주석이다. 같은 도구가 두 행이면 형식 오류(어느 쪽이
#   이기는지 알 수 없다). CR(CRLF)·BOM 도 형식 오류다 — 눈에 안 보이는 채로 도구명을
#   어긋나게 만들어 게이트를 통째로 미등재로 접는 부류라 여기서 소리를 낸다.
#
# ── 예시 (주석이다. 그대로 풀어 쓰지 마라 — 실측 없이 켜면 정상 발행이 막힌다) ──
#   mcp__example__createIssue	1	no	-	-
#   mcp__example__addComment	1	yes	-	body
#   mcp__example__transitionIssue	2	no	-	-
#   mcp__example__uploadArtifact	1	no	file_path	-
#
# ── 등록 절차 (한 도구를 켤 때 이 체크리스트를 **실세션에서** 채운다) ──
# 이 항목들은 문서를 읽어서는 알 수 없다. 실제 세션에서 그 도구를 한 번 호출해
# PreToolUse 훅에 도착한 payload 를 캡처해야 나온다(캡처 방법: 임시로
# `ECC_DISABLED_HOOKS=publish:receipt` 를 두고 호출한 뒤 훅 stdin 을 파일로 떠 보기).
#
#   [ ] ① 도구 **전체 이름**을 payload 의 최상위 tool_name 에서 그대로 옮겼다
#         (문서에 적힌 이름이 아니라 훅이 실제로 받는 이름이다).
#   [ ] ② tool_input 의 **필드 이름**을 실물로 확인했다(본문·파일 경로가 어느 키인가).
#   [ ] ③ stdin 원본성: 훅이 받는 payload 가 **호출 원문**인지, 도구 제공자가 이미
#         정규화한 뒤인지 확인했다. 이미 정규화됐다면 "중복 키 거부"의 보장 범위가
#         그만큼 좁아진다는 사실을 알고 등록하는 것이다(ADR-0018 2절 공시).
#   [ ] ④ Artifact 계열이면 파일 경로가 tool_input 안에 있는지 확인했다. **없으면
#         등록하지 않는다** — 경로가 없으면 내용을 digest 에 묶을 수 없다.
#   [ ] ⑤ payload 에 **float 이 실재하는지** 확인했다. 있으면 그 도구는 등록 보류이거나
#         해당 필드를 문자열로 정규화한 뒤에만 등록한다(digest 함수가 float 을 거부한다).
#   [ ] ⑥ **환경 정체성 실측**: 발급기를 돌리는 환경의 `publish_serializer_identity` 값과
#         훅이 도는 환경의 값이 **같은지** 확인했다. 다르면 발급 즉시 소비가 불가능하다
#         (게이트가 "직렬화 드리프트 의심"으로 deny 한다). 확인 명령:
#           bash -c '. .claude/hooks/_common.sh; publish_serializer_identity; echo'
#   [ ] ⑦ min_tier·waivable 판정을 리뷰 규약(harness-orchestrator SKILL.md 발행 리뷰
#         규약)의 분류에 맞췄다. **판정이 불명이면 2다**(fail-closed).
#
# ── 여기 없는 것은 막지 않는다 ──
# 이 파일은 **알려진 도구만** 안다. 새 도구·중립적인 이름의 mutation 도구는 등록 전까지
# 무방비이고, Bash 의 `git push`·`gh`·`curl` 은 애초에 이 게이트의 사정권 밖이다.
# 전체 잔존 위험 목록은 docs/decisions 의 ADR-0018 에 있다.
#
